# 证据包、草稿预检与虚构写回模拟：独立验收

日期：2026-11-13。范围：只读证据包及采集编排、草稿预检报告、应用内报告窗口、纯内存模拟器和现有写入拒绝策略之间的边界。基线为离线草稿版本 `7b328ca`。

本轮没有连接、读取或写入真实手机，也没有执行真实 `--roundtrip` 或带有效范围确认的真机采集命令。真实适配器仅通过源码检查和替换为假 SDK 的测试验证；真实设备行为仍未验证。

- 完整仓库：**608 项测试、543 项子测试通过，0 项失败，测试进程退出码 0**，耗时 10.09 秒。

上述结果是源码与模拟验证；应用包签名、安装、原生窗口和导出交互由主任务另行核验。

## 核对的边界

| 边界 | 验证内容 |
|---|---|
| 本地备份不是新设备观测 | 导入只产生已有布局的观察记录，不虚构设备身份、安装清单、第二次布局、网格或新鲜度。报告保持阻塞。 |
| 空结果与失败不同 | 成功返回空字典可标记该查询完成；失败或未采集不能替换为空字典，也不构成完整资源库清单。空清单与已显示 App 冲突时另行报告。 |
| 查询顺序与中断 | 对每一采集阶段注入失败，确认停止后续查询、没有重试、调用关闭；后续阶段保持未采集。失败记录仅含稳定代码，不导出模拟异常中的敏感字符串。 |
| 收尾失败 | 即使全部读取完成，关闭失败也会在预检中明确显示，不被成功观察掩盖。 |
| 范围与类型 | 请求选项按类型敏感的序列化核对，`show_placeholders=1` 不能冒充 `True`；非法范围、字段、布尔版本和错误根格式被拒绝。 |
| 缺失信息不能变绿 | 几何、隐藏页、组件设置、隐藏网页快捷方式保持未知；文件不能把这些值改成 verified。即使构造看似完备的 USB 标签记录，报告仍为 blocked、`can_write=False`。 |
| 新鲜度和身份 | 检查五分钟默认窗口、超前时间，以及采集前后设备指纹、型号、iOS 和构建号变化。哈希一致只说明内容一致，不提供设备认证。 |
| 快照与草稿 | 草稿基线与观察值不一致、采集前后布局变化、内部草稿状态与操作历史不一致，均明确失败。类型比较能识别 `True` 与 `1` 的差异。 |
| 只读适配器 | 只接受列明的读取项目，未知动作在建立连接前拒绝；安装查询包含占位应用且仅请求声明属性；身份读取为新请求，并仅导出标识摘要。 |
| 本地 USB 限制 | 证据适配器显式固定本地 mux 地址，macOS 为 `/var/run/usbmuxd`，Windows 为 `127.0.0.1:27015`；模拟的远程环境覆盖不能重定向它。`autopair=False` 防止此路径新建信任。 |
| CLI 授权门槛 | 帮助、本地导入、缺少范围确认的拒绝分支不能构造设备适配器。测试在设备导入/工厂位置设置失败陷阱，没有运行真实采集分支。 |
| 模拟器不是发送器 | 只接收固定类型的数据情景，内部创建不可继承的内存假传输，不接受真实设备对象或可执行回调。 |
| 无回复与失败 | 发送超时、断线和无回复可能已经产生假副作用；每个情景最多一次假发送，零自动恢复。有限次重新读取使用不同假连接编号。 |
| 严格读回 | 组件所选成员丢失、堆叠重排、建议开关改变、字节和日期破坏、布尔变整数、增加应用/页面均不能被忽略。 |
| 结果不能授权写回 | 假读回匹配仅为 `EXPORTED_FIELDS_MATCH_ONLY`，始终保留未验证因素，`fully_verified=False`、`can_write=False`。现有 Duo 写入策略仍拒绝候选布局。 |
| 界面离线隔离 | 创建、查看、导入证据、刷新和导出报告时，将 socket、USB 就绪查询、设备工厂及所有设备工作线程入口替换为失败陷阱；均未调用。 |
| 报告对应真实草稿 | 窗口先验证传入草稿的当前状态，再建立独立副本；报告打开后，原草稿的后续修改不改变已有报告快照。 |
| 文本呈现 | 含 HTML 标签的模拟 App 名以原样纯文本呈现，不作为图片或富文本解释。 |
| 文件保护 | `.hsevidence`、`.hspreflight` 使用独立格式和私有文件权限；不能覆盖 `.plist`，也不能覆盖伪装成这些扩展名的原始布局。 |
| 不可作为恢复文件 | 即使将证据或报告改名为 `.plist`，再构造同设备有效内容摘要，恢复层仍在查询假手机之前拒绝根结构。 |
| 来源与归档 | 证据、报告及私有目录从 Git 和源码归档排除；研究模块的允许导入仅扩大到明确的纯数据边，并继续审查其依赖链。 |

## 独立审查发现与处理

1. **完成读取不等于采集正常结束。** 预检最初没有展示 `close_error_code`，全部观察成功会掩盖关闭失败。已增加采集完成状态检查。
2. **查询集合不重叠不等于覆盖合理。** 两份成功但为空的安装清单，即使与可见 App 明显矛盾，原检查也只看到“没有交集”。已增加可见普通 App 的标识覆盖检查，并保留“单次查询成功”与“整体覆盖完整”的区别。
3. **窗口不能悄悄修复被审查对象。** 报告窗口最初只从基线重放历史，可能忽略传入当前状态中的额外损坏。独立反例先失败；修复为先验证传入草稿后再建立副本，现已通过。
4. **改名文件不能被覆盖或当作备份。** 报告覆盖前增加已有报告格式检查；测试证实，误改扩展名的布局文件保持原样，证据/报告也不能进入恢复通道。
5. **SDK 环境变量可能扩大连接范围。** 所锁定 SDK 会在未指定地址时读取 `USBMUXD_SOCKET_ADDRESS`。证据适配器已对枚举与连接同时显式指定本地地址，测试覆盖 macOS 与 Windows；普通设备桥的既有行为未在本阶段修改。

这些缺陷影响证据准确性、连接范围或本地数据保护。发现和修复均通过假对象及本地测试完成，没有导致真实手机访问。

## 明确未验证的内容

真实只读采集命令尚未在手机上执行。测试不能证明某个 iOS 版本会按请求返回完整的 User/System、卸载占位、格式 3 布局或所有组件字段。即便读取完毕，USB 未导出的隐藏页、空隙、组件配置和隐藏网页快捷方式仍然是未知信息。

模拟器处理的是预先给定的虚构故障事件，不是实际网络超时、内核断线、iOS 持久化或恢复能力测试。假读回匹配不能推导真机无损。收据的源标签与 SHA-256 用于组织和完整性核对，不是密码学设备证明。

本阶段未放宽 `write_policy.py`、备份写入保护或设备工作线程的现有拒绝策略，也没有把模拟器连接到任何真实发送接口。真实采集和真实写入仍是不同的后续操作范围，不能由本报告或导出文件自动授权。
