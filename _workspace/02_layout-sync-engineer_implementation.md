# Phase 2 산출물 — 기기 프로브와 기반 계층

**날짜:** 2026-08-19
**상태:** 구현 완료 · 실기기 검증 대기

## 무엇을 만들었나

Phase 1a에서 `setIconState` 의 존재가 확인되었지만, 그것이 **이 사용자의 기기에서 실제로
동작하는지**는 `[미검증]` 이다. 그래서 첫 산출물을 UI가 아니라 **프로브**로 정했다.
UI를 먼저 만들면 검증 없이 쓰기 기능을 얹게 되고, 그것이 이 프로젝트에서 가장 하면 안 되는 일이다.

| 파일 | 역할 | 대응 REQ |
|------|------|---------|
| `src/ipsm/logging_setup.py` | 세션 로그 · 산출물 보존 · zip 보고서 | REQ-004 |
| `src/ipsm/device.py` | pymobiledevice3 를 감싸는 유일한 계층 · 오류 번역 | REQ-001, 002, 005 |
| `src/ipsm/iconstate.py` | 레이아웃 해석 (원본 보존) · 비교 · diff 요약 | REQ-017 |
| `src/ipsm/backup.py` | 백업·복원 · 모든 쓰기의 단일 관문 | REQ-010, 011 |
| `src/ipsm/probe.py` | 실기기 진단 CLI · 항등 왕복 시험 | REQ-003 |
| `tests/test_core.py` | 기기 없이 확인 가능한 것 (9개, 전부 통과) | - |
| `install.ps1`, `run_probe.bat`, `README.md` | 사용자가 실행할 수 있는 형태 | - |

## 설계에서 강제한 것

1. **쓰기는 `guarded_write()` 한 곳만 거친다.** 백업 실패 시 `BackupError` 를 던지고 쓰지 않는다.
2. **백업은 저장 직후 되읽어 대조한다.** 복원 불가능한 백업은 없는 것보다 나쁘다.
3. **프로브의 기본은 읽기 전용.** 쓰기는 `--roundtrip` + 대화형 확인 질문 둘 다 있어야 일어난다.
   비대화형 실행(파이프·스케줄러)에서는 확인 질문이 자동으로 '아니오'가 된다.
4. **해석은 원본 위의 뷰.** `IconState.parse()` 는 `deepcopy` 로 입력을 건드리지 않으며,
   모든 `Item` 이 `raw` 를 들고 있다. `Unknown` 은 `movable = False`.
5. **비교에서 휘발성 필드 제외.** `iconModDate` 로 판정하면 정상 동작이 항상 실패로 보고된다.

## 구현 중 발견한 문제 (해결됨)

| 문제 | 영향 | 대응 |
|------|------|------|
| 한국어 Windows 콘솔(cp949)이 `✔ ✗ ⓘ ⚠` 를 인코딩하지 못해 로깅이 죽는다 | 진단 도구가 진단 중에 깨진다 — 실기기 세션에서 최악 | `logging_setup` 이 콘솔 인코딩을 미리 시험하고 ASCII 표시로 낮춘다. 파일 로그는 항상 UTF-8 원본 유지. 추가로 `stdout.reconfigure(errors="replace")` 로 최종 방어 |
| `pip install pymobiledevice3` 가 `lzfse` C 확장 빌드에서 실패 | 사용자가 설치 단계에서 막힌다 | `install.ps1` — `--no-deps` 로 본체 설치 후 필요한 의존성만 개별 설치. `lzfse` 는 펌웨어 압축 해제용이라 홈화면 작업에 불필요 |
| 이 PC에 Apple Devices/iTunes 미설치 (`ConnectionFailedToUsbmuxdError`) | 프로브 실행 불가 | 사용자 안내로 번역됨. **실기기 시험 전 설치 필요** |

## 실기기 실행으로 판정될 `[미검증]` 항목

Phase 1a에서 남긴 7개 중 프로브가 답하는 것:

| 질문 | 어떻게 답이 나오나 |
|------|------------------|
| `setIconState` 가 이 iOS 버전에서 적용되는가 | `--roundtrip` 결과 |
| **변경된** 상태도 적용되는가 | 항등 왕복 통과 후 별도 시험 (Phase 3) |
| 기기 잠금 해제가 필요한가 | 잠금 상태에서 먼저 실행해 보면 드러난다 |
| 위젯이 iconState에 어떻게 표현되나 | `unknown_items.json` 산출물 |
| 빈 슬롯 표현 | `icon_state_before_readable.json` |
| App Library·숨긴 페이지 포함 여부 | 페이지 수를 실제 홈화면과 대조 |
| 잘못된 상태를 보내면 어떻게 되나 | **의도적으로 시험하지 않는다** (Phase 1a 결정 유지) |

## 갱신 (2026-08-20) — 실기기 판정 결과

**상태:** 실기기 검증 완료. 위 "다음 단계"의 1~3 이 모두 끝났다.

### REQ-003 항등 왕복 — 통과 (2026-08-19, iPhone 14 / iOS 26.1 [23B85])

309개 항목이 순서·폴더 내용·날짜까지 그대로 보존됐다. 손실 0, 이동 0.

**단 하나의 부작용:** 앱 라이브러리에만 있던 앱을 iOS 가 마지막 페이지 끝에 되붙인다.
`setIconState` 에는 "설치됐지만 홈화면에 없음"을 표현할 방법이 없기 때문이다. 백업 복원도
쓰기이므로 **이것만은 백업으로 되돌려지지 않는다.**

이 발견으로 판정 기준을 **"완전 동일"에서 "손실·이동 없음"으로 정정**했다. 되붙은 항목은
`WriteComparison.appended` 로 따로 세고 실패로 보지 않는다.

### 위 표의 `[미검증]` 항목 — 지금 상태

| 질문 | 결과 |
|------|------|
| `setIconState` 가 이 iOS 버전에서 적용되는가 | **예** (항등 왕복 통과) |
| **변경된** 상태도 적용되는가 | `[미검증]` — 편집 후 쓰기는 아직 하지 않았다 |
| 기기 잠금 해제가 필요한가 | 잠금 해제 + 신뢰 상태에서만 시험함. 잠금 상태는 `[미검증]` |

| 문제 | 영향 | 대응 |
