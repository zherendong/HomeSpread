## 安全规则及后续修复

1. **统一写入保护。**设计要求所有写入经过 `guarded_write()`，备份失败抛出 `BackupError` 并停止。2026-11-13 审计发现原诊断/验证脚本仍有直接写入旁路，已统一修复，源码检查覆盖应用与脚本。
2. **备份重新读取校验。**不能将不可恢复的文件报告为有效备份。当前版本还采用设备独立目录、持久化写入、唯一命名、归属元数据和内容摘要。
3. **诊断默认只读。**真实往返写入必须同时提供 `--roundtrip` 并在交互终端确认；管道或调度器等非交互执行不自动同意。
4. **解析只是原始数据上的视图。**`IconState.parse()` 使用 `deepcopy`，每个 `Item` 保留 `raw`，未知项 `movable = False`。当前写前校验进一步阻止未知项因其它编辑而发生间接位移。
5. **写后比较区分易变字段。**比较忽略 `iconModDate` 等已知易变时间字段；备份的原始值仍必须完整保留。当前比较还检查同 ID 条目的内容变化，不能只比较位置。
6. **快照不能过期。**普通编辑传入读取时的 `expected_state`，写入前重新读取并精确比较；手机端已变化则停止。

## 原实现阶段遇到并处理的问题

| 问题 | 影响 | 处理 |
|------|------|------|
| 韩文 Windows 控制台 cp949 无法编码 `✔ ✗ ⓘ ⚠`，导致日志出错 | 诊断工具在记录问题时自身失败 | `logging_setup` 预检控制台编码，必要时降级为 ASCII；文件保持 UTF-8；`stdout.reconfigure(errors="replace")` 提供兜底 |
| `pip install pymobiledevice3` 在 `lzfse` C 扩展构建时失败 | 用户无法完成 Windows 安装 | 原 `install.ps1` 通过 `--no-deps` 安装主体，再逐个安装所需依赖；`lzfse` 属于固件解压功能，主屏幕操作不使用它。macOS 使用独立的锁定依赖安装流程 |
| 当时的 Windows 电脑未安装 Apple Devices/iTunes，出现 `ConnectionFailedToUsbmuxdError` | 无法运行诊断 | 将异常转为安装提示；该历史环境需先安装 Apple 连接组件。macOS 使用系统服务及 Finder 信任，不执行该 Windows 准备步骤 |

## 原计划由实机诊断回答的问题

| 问题 | 证据取得方式 |
|------|------------------|
| 此 iOS 版本是否接受 `setIconState` | 明确确认后的 `--roundtrip` 结果 |
| 编辑后的状态是否接受 | 往返通过后另行确认并执行编辑测试，不能由恒等结果推断 |
| 是否需要解锁 | 观察锁定状态下的连接/服务响应 |
| 小组件的 iconState 表示 | `unknown_items.json` 原始样本 |
| 空位的表示 | `icon_state_before_readable.json` |
| 是否包含 App 资源库、隐藏页面 | 原始结果与实际页面核对；不能只用页数证明全部状态被返回 |
| 错误状态的后果 | **不故意向用户设备发送损坏数据**，保留原决定 |

## 原阶段推进顺序

以下是当时的开发顺序，不是当前待执行清单：

1. 执行 `run_probe.bat`，查看只读结果。
2. 经用户同意执行 `run_probe.bat --roundtrip`，判断 REQ-003。
3. 通过后定义 `02_contracts/`、采用 ADR-001，再实现画布界面（REQ-012～016）。
4. 失败则分析日志，重新评估 `layout-diff-planner` 的条件性备用方案。

当前版本不会在失败后自动启用手势执行。普通编辑要求本次会话 `write_verified` 为真，正常流程先通过原样回写兼容性测试。明确确认的同设备备份恢复是独立入口；恢复成功且读回比较安全也会建立或刷新该标记。

## 上游更新：2026-08-20 实机结果

**当时状态：**上述开发顺序第 1～3 步已完成。这里的“完成”仅指记录中的上游设备。

### REQ-003 原样回写通过

环境：2026-08-19，iPhone 14 / iOS 26.1 `[23B85]`。309 个条目的顺序、文件夹内容和日期均保留；丢失 0、移动 0。

**观察到的副作用：**仅在 App 资源库中的应用被 iOS 放回最后一页。该接口无法表达“已安装但不在主屏幕”的完整隐藏状态；恢复也会执行写入，因此**备份恢复不能消除这一副作用**。

由此，上游将通过标准从“完全相同”改为“没有丢失或意外位移”，新增项单独计数。当前字段名为 `WriteComparison.added`；旧文曾写成 `appended`，已与实际接口统一。当前 `.safe` 还要求没有 `changed` 内容差异。
