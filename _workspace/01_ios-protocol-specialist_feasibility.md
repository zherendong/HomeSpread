# 可行性调查——iPhone 主屏幕布局的读写路径

**原始调查日期：**2026-08-19。**文档校订日期：**2026-11-13。

**结论：存在写入路径。** 项目最初关于“未越狱 iPhone 没有布局写入 API”的假设不成立。能够在库源码中找到命令，不等于已经验证任意设备和 iOS 版本都能安全接受该命令。

本文保留原调查的证据、待验证问题和候选方案。当前 macOS 移植版仅使用 USB；本机已完成只读连接和备份验证，未执行真实桌面写入。当前写入、备份、恢复规则见 `02_contracts/` 和 `../SECURITY_AUDIT.zh-CN.md`。

## 1. 关键发现——`com.apple.springboardservices`

iOS 提供名为 **`com.apple.springboardservices`** 的普通 lockdown 服务。库实现包含主屏幕布局的读取和写入命令。

| 命令 | 功能 | 原调查确认方式 |
|------|------|------|
| `getIconState` | 返回整个主屏幕布局，包括页面、文件夹和程序坞 | `[源码/文档已确认]` |
| `setIconState` | **替换整个主屏幕布局** | `[源码/文档已确认]` |
| `getHomeScreenIconMetrics` | 返回网格行数、列数、间距等布局参数 | `[源码/文档已确认]` |
| `getIconPNGData` | 返回应用图标 PNG | `[源码/文档已确认]` |
| `getInterfaceOrientation` | 返回屏幕方向 | `[源码/文档已确认]` |

依据：原调查直接阅读了 `pymobiledevice3/services/springboard.py` 的 `master` 分支。以下为当时核对的接口示例，保留原技术标识符：

```python
async def set_icon_state(self, newstate=None) -> None:
    state = {} if newstate is None else newstate
    await self.service.send_recv_prefixed(
        build_plist({"command": "setIconState", "iconState": state}))
```

### 这一发现带来的设计变化

| 项目 | 最初假设 | 调查结果及适用限制 |
|------|----------|------|
| 写入方法 | 重放拖动手势 | 发送一次完整 plist |
| 移动一个图标的成本 | 数秒 | 完整布局通过一次服务调用发送；本机耗时须实测 |
| 前提条件 | 开发者模式、DDI、WDA 签名 | 此服务路径需要配对信任，不要求上述开发工具 |
| 恢复 | 无法恢复 | 可以再次发送已保存的 iconState；**不能保证完全恢复所有系统效果**，App 资源库回填无法靠恢复撤销 |
| 部分失败 | 手势执行随时可能中断 | 一次提交整份布局；**不据此声称事务性、掉电原子性或必然全成全败** |
| 网格参数 | 需要测量和推断 | 可向 `getHomeScreenIconMetrics` 查询，缺失时须明确使用回退值 |
| 应用识别 | 辅助功能树、OCR、图标匹配 | 布局内含标识符；后续实测确认须优先使用 `displayIdentifier`，卸载保留图标的应用可能没有 `bundleIdentifier` |

采用这条路径后，设备端手势重放、辅助功能树解析、图标图像识别及手势执行检查点/恢复不再是主实现。编辑模型仍需计算插入和跨页顺移，不能把“不再模拟设备手势”理解成“不需要布局规则”。

### 先例

`libimobiledevice/sbmanager` 曾利用该服务实现桌面端主屏幕编辑 GUI `[文献]`。它属于 iOS 3～6 时期的项目，原调查时已不再维护，不能作为当前 iOS 兼容性的证明。

## 2. 原调查中的待验证问题

**下列问题在原调查阶段均未通过实机确认。不能仅凭接口存在，将其答案当作事实。** 后续上游 iPhone 14 / iOS 26.1 的测试记录只覆盖该环境；当前 Mac 上的 iPhone / iOS 27.3 仍未验证写入。

| 问题 | 重要性 | 验证方法 |
|------|-----------|----------|
| 当时所讨论的 iOS 18/26 是否实际接受 `setIconState` | 若不接受，直接写入路径不成立 | 经用户确认后进行原样回写，再读取并比较 |
| 修改后的状态是否生效，而非只有原样回写生效 | 原样回写通过不代表编辑一定生效 | 经确认移动一个图标，再读取比较 |
| 是否需要解锁 | 决定连接及操作提示 | 在授权的验证范围内检查锁定状态响应 |
| 小组件如何在 iconState 中表示 | 如果未被返回，整份写入可能损失小组件 | 读取含小组件页面的原始数据 |
| iOS 18+ 自由布局中的空位如何表示 | 影响编辑模型 | 读取带空位页面的原始数据 |
| App 资源库、隐藏页面、专注模式关联页面如何处理 | 整份覆盖可能影响这些状态 | 检查查询结果及明确授权的实机行为 |
| 发送错误 iconState 会发生什么 | 涉及失败模式和保护设计 | **不故意向用户设备发送损坏布局** |

原计划在往返测试失败时放弃直接写入并重新评估手势路径。当前规则是：失败后禁用普通编辑的“应用”，保留经过同设备归属校验、再次备份和明确确认的恢复入口。**手势路径只是条件性研究备选，不会在失败后自动启用。**

原调查还确认，pymobiledevice3 的 `wallpaper-preview-image --reload` 使用 `reload_icon_state()` 执行 get → set 往返 `[源码已确认]`。这属于实现层面的旁证，不是所有现行 iOS 版本都能安全写入的实测证据。

## 3. 工具选择

### pymobiledevice3

| 项目 | 原调查内容 | 确认方式 |
|------|------|------|
| 语言 | Python 3 实现，不需要另外调用设备管理可执行文件 | `[源码/文档已确认]` |
| 许可证 | **GPL-3.0-or-later** | `[源码/文档已确认]` |
| iOS 17+ 能力 | 库支持 RemoteXPC 隧道 | `[源码/文档已确认]`；本应用不因此启用隧道 |
| 连接能力 | 库支持 USB、Wi-Fi、RemoteXPC | `[源码/文档已确认]`；当前应用仅允许 USB |
| SpringBoard | 普通 lockdown 服务，无需 DDI | `[源码/文档已确认]` |
| Windows | 使用 Apple Devices 或 iTunes 提供的连接组件；原调查描述为基于 pyusb | `[文献]`，原调查时 `[未验证]` |

**候选替代：**`libimobiledevice`，C 实现、LGPL-2.1，提供相同的 `sbservices` 功能。Python 端使用它需要额外绑定和二进制分发。因此仅在 pymobiledevice3 不再适用时重新评估，不列为已安排的迁移任务。

### 许可证决定

项目接受 pymobiledevice3 的 GPL-3.0-or-later 许可条件，整体按 **GPL-3.0-or-later** 分发，并随制品提供许可和对应源码获取方式。原调查以个人工具、没有闭源商业分发计划为背景作出此决定。若明确提出闭源分发需求，须先重新审查依赖和许可方案；这是一项条件性重审触发条件，并非已计划的产品方向。

## 5. 原调查建议及落实边界

1. 主实现从手势路径转向 springboardservices。这是已采用的技术选择。
2. 先实现诊断工具：连接、导出 `getIconState` 原始结果和网格参数、明确确认后的原样回写测试，以及全过程日志。单次往返测试不能回答小组件、隐藏页面等全部待验证问题。
3. 保留 `layout-diff-planner` 技能，供直接写入不适用且用户另行选择研究手势方案时使用；不自动重启该方案。
4. 备份完整性、原始字段保留、设备归属、过期状态检测及写后比较共同构成安全边界。备份提供恢复依据，不保证所有系统副作用可逆。
