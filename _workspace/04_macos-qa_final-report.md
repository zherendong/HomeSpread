# macOS 中文版独立验收记录

日期：2026-11-13。范围：本地 HomeSpread macOS 中文移植的界面、平台适配、设备工作线程与备份层边界。测试环境为 Apple Silicon macOS、CPython 3.12、PySide6 Essentials 6.12.0；Qt 自动测试使用 offscreen 平台。

## 自动化结果

执行命令：

```sh
QT_QPA_PLATFORM=offscreen \
HOMESPREAD_DATA_DIR=/private/tmp/homespread-qa-data \
HOMESPREAD_CACHE_DIR=/private/tmp/homespread-qa-cache \
.venv/bin/python -m pytest tests -q --tb=short
```

结果：**173 项测试通过，351 项子测试通过，0 项失败。** 测试未跳过 Windows 逻辑：8 项 Windows 专用检查使用隔离的平台模拟，原有断言仍执行；Mac 路径和连接行为有独立测试。

新增 `tests/test_macos.py` 的 25 项检查覆盖：

- macOS 使用 `/var/run/usbmuxd` 本地 Unix socket，设置连接超时。
- 移动或重命名 `.app` 不改变备份位置；测试目录覆盖与私有目录权限生效。
- 连接服务不可用时显示中文访达操作提示，不能打开 Microsoft Store。
- 主界面中文、撤销与分组快捷键以及未连接时的写入禁用状态。
- 从文件导入的预览即使被编辑，也不能提交到已连接手机。
- UI 将读取时的原始布局传给工作线程，工作线程在排队前复制输入，避免可变数据改变待执行操作。
- 设备操作进行中拒绝关窗；设备库导入失败可报告，并拒绝后续工作。
- 来自应用名称的内容以纯文本显示，应用前必须勾选确认。
- 恢复后核对丢失条目；UI 共用结果核对路径，并说明内容损坏。
- 建立设备连接后先绑定该设备的备份目录。
- 未经本次会话原样写回校验，UI 和工作线程都拒绝编辑应用；只有未编辑的真实设备布局可发起校验，取消确认不会写入。
- 校验使用备份保护，比较读回结果后才设置通过标记；丢失条目、操作失败或重新读取会撤销编辑写入许可。
- 校验失败后仍保留独立的备份恢复通道，恢复前显示额外风险并要求用户确认；普通读取不会自动触发校验或写入。

## 安全边界

| 检查 | 结果与依据 |
|---|---|
| 写入前预览与确认 | UI 应用和恢复使用明确的确认对话框；未勾选确认时按钮禁用。 |
| 设备会话兼容性门禁 | 编辑应用必须在本次会话通过明确确认后的原样写回校验；读取不触发该动作。失败后仍可明确确认恢复同设备的完整备份。 |
| 备份失败停止写入 | `guarded_write` 的失败注入测试确认没有设备写入；二进制备份、持久化和完整性记录在写入前核对。 |
| 不同设备隔离 | 备份目录绑定设备指纹；不属于当前设备或完整性记录缺失的备份不能恢复。 |
| 过期布局 | 手机现状与读取时布局不一致时拒绝应用。 |
| 未知元素 | 写入保护拒绝未知项移动、原始内容变更，以及已知叶节点丢失或重复。 |
| 写入后核对 | 应用和恢复都比较预期结果与重新读取的结果；丢失、意外移动及内容损坏会给出警告。 |
| 单次操作与退出 | 不排队执行多个设备动作；进行中的动作阻止关闭窗口。没有自动连续写入重试。 |
| 直接写入旁路 | 程序、诊断 CLI 和验证脚本统一调用 `guarded_write`；验证脚本的写入只出现在显式 `--apply` 的第二阶段。 |

独立检查发现上游原有 UI 只检查内存恒等，并未落实真实设备写回校验。修改版已增加本次会话的校验门禁，避免把其它设备的历史成功记录当作当前手机的兼容性证据。备份恢复保留为显式确认的恢复路径，否则校验写入失败后会阻断用户恢复；这项区别已写入更新后的界面契约。当前手机的实际写入兼容性仍未验证。

本次没有验证断线写入、未知 iOS 布局写回、恶意或畸形布局在真机上的行为。App 资源库中的应用可能在写入后重新出现在桌面，备份恢复不能消除这项 iOS 行为。自动测试只能证明检查过的程序路径和数据保护，不能证明未公开的 iOS 服务在所有机型或版本上安全。
