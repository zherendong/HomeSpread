## 1. 먼저 답이 나온 것

| 물음 | 답 | 근거 |
|------|-----|------|
| GPL 프로그램을 스토어에 올려도 되는가 | **된다** | 개발자 계약은 개발자가 **자기 라이선스 약관을 대신 제출**하는 것을 허용하고, FOSS 가 요구하는 범위에서 표준 약관의 역공학·복제·재배포 금지 조항을 **넘어서도록 명시적으로 허락**한다. VLC 가 이 경로로 올라가 있다 `[확인됨(2차)]` |
| 후원 버튼을 PayPal 로 두어도 되는가 | **된다 — 아무것도 돌려주지 않는 한** | 정책 10.8.2: 자발적 후원은 Microsoft 결제 API 또는 **안전한 제3자 결제 API**로 받을 수 있다. 단 그 대가로 디지털 재화·기능·광고 제거를 주면 즉시 인앱 구매 API 로 넘어가야 한다 `[확인됨]` |
| 개인 계정으로 되는가, 회사 계정이 필요한가 | **개인 계정으로 된다** | 정책 10.8.3 의 회사 계정 요구는 **주 기능**이 금융 정보를 요구할 때다. 우리 주 기능은 홈화면 편집이고 후원은 곁가지다 `[확인됨]` |
| 개인정보 처리방침이 필요한가 | **반드시 필요하다** | 정책 10.5.1: Win32/데스크톱 브리지 제품은 **언제나** 개인정보 처리방침을 둔다 `[확인됨]` |
| MSIX 로 묶으면 `127.0.0.1:27015` 가 막히는가 | **막히지 않는다** | `Windows.FullTrustApplication` 으로 묶은 데스크톱 앱은 AppContainer 밖에서 돌아 일반 데스크톱 앱과 같은 권한을 갖는다. 2026-08-26 에 실제 `.msix` 를 `C:\Program Files\WindowsApps\` 에 설치해 확인했다 — 시작 안내판이 `동작 True · 설치 True (127.0.0.1:27015)` 를 적었다 `[확인됨]` |

## 2. 포장 방식 — 두 갈래

> 2026-08-21: 어느 쪽으로 가든 필요한 **폴더 배포(onedir)로 이미 전환했다** —
> `dist\HomeSpread\`. MSIX 는 exe 하나를 감싸는 그릇이 아니라 파일 목록을 담는
> 그릇이라 이 모양이 전제다. 덤으로 시작 시간이 21초 → 2.3초가 됐다.

이 두 갈래는 Partner Center 의 **`+ 신상품`** 목록에서 그대로 갈린다 —
**`MSIX 또는 PWA 앱`** 과 **`EXE 또는 MSI 앱`**. 나머지 둘(`GDK game`,
`MSIX 또는 PWA 게임`)은 게임용이라 우리 것이 아니다. 이 선택은 제품을 만들 때
정해지므로, 만들기 전에 결정을 끝내 둔다.

| | `MSIX 또는 PWA 앱` | `EXE 또는 MSI 앱` (정책 10.2.9) |
|---|---|---|
| 사용자 경험 | 스토어에서 설치·갱신이 자동 | 스토어가 **우리가 대는 URL** 의 설치 파일로 보낸다 |
| 서명 | **스토어가 Microsoft 인증서로 다시 서명한다.** CA 인증서·pfx·USB 토큰 전부 불필요 `[확인됨]` | **우리가 CA 인증서를 사서 Authenticode 서명한다.** 스토어는 EXE/MSI 를 다시 서명하지 않는다 `[확인됨]` |
| 호스팅 | Microsoft CDN (무료) | **우리 인프라나 CDN.** 판마다 다른 URL 을 대고, 올린 뒤 그 URL 의 파일은 바뀌면 안 된다 |
| 갱신 | 스토어가 한다 | 새 판마다 **새 버전 URL** 을 Partner Center 에 다시 등록한다 |
| 만들어야 할 것 | `AppxManifest.xml` + `makeappx` | **조용한 설치기**(설치 중 UI 금지, UAC 만 허용) · 단독 오프라인 설치기(실행 중 내려받기 금지) |
| 위험 | ~~루프백~~ · ~~파일 쓰기 경로 가상화~~ — 둘 다 2026-08-26 에 걷혔다(4-2). 남은 것은 **제어된 폴더 액세스**(아래) | 인증서 비용이 **해마다** 든다 · 갱신·호스팅을 우리가 떠맡는다 |

**권한다: `MSIX 또는 PWA 앱`.** 갈림길의 무게는 서명에 있다 — MSIX 는 스토어가
서명해 주므로 인증서를 살 필요가 없고, EXE/MSI 는 **반드시** 사야 한다. 지금 우리에게
남은 MSIX 쪽 위험(루프백·자료 폴더)은 **돈이 아니라 시험으로** 걷어낼 수 있는 것이다.
그러니 4-2 의 A·B 를 먼저 하고, 거기서 막히면 그때 EXE/MSI 로 물러선다.
`dist\HomeSpread\` 는 폴더 배포라 어느 쪽이든 그대로 쓴다 — 다만 EXE/MSI 로 가면
그 폴더를 감쌀 설치기(Inno Setup 등)를 **따로 만들어야 한다.**

> **자료 폴더 — 답이 나왔다(2026-08-21).** `C:\Program Files\WindowsApps\` 는 소유자가
> `NT AUTHORITY\SYSTEM` 이라 **관리자 권한으로도** 쓸 수 없다(직접 확인). 그래서
> `paths.data_root()` 가 포장된 설치에서만 **문서 폴더**(`문서\HomeSpread\`)로 간다.
> `%LOCALAPPDATA%` 는 답이 아니다 — 포장된 앱에서는 `Packages\...\LocalCache\` 로
> 조용히 옮겨져 정확히 "사용자가 찾을 수 없는 곳"이 된다. 포장 판정은
> `GetCurrentPackageFamilyName` + `is_frozen()` 둘 다로 한다. 아이콘 캐시만 `%TEMP%` 다.
> **실제 패키지에서 확인했다(2026-08-26).** 서명 없는 `.msix` 를 만들어
> `C:\Program Files\WindowsApps\` 에 설치했고(그 폴더는 실제로 쓸 수 없었다),
> 앱은 `문서\HomeSpread\` 에 `backups\` 와 `logs\` 를 만들었으며 아이콘 캐시는
> `%TEMP%\HomeSpread-cache` 에 그대로 있었다. `Packages\...\LocalCache\` 로 새어 나간
> 우리 자료는 하나도 없다 — 그 아래 있는 것은 전부 Windows 가 만든 뼈대뿐이다 `[확인됨]`.

## 4. 올리기 전에 반드시 끝내야 하는 것

1. ~~**`product.SOURCE_URL` 채우기**~~ — 끝났다 (2026-08-21).
   `https://github.com/humanlyj/HomeSpread` 를 `product.SOURCE_URL` 에 적었고, 정보 창이
   링크로 보여준다. 같은 주소가 Partner Center 의 개인정보 처리방침 칸도 채운다
   (`product.PRIVACY_URL` → `.../blob/main/PRIVACY.md`)
2. ~~**MSIX 실제 패키지로 루프백·백업 쓰기 시험**~~ — 끝났다 (2026-08-26).
   - **A. 느슨한 등록** — `HomeSpread.Dev_1.0.19.0_x64` 로 등록. `is_packaged()` 가 참이
     되어 자료가 `문서\HomeSpread\` 로 갔고, 27015 루프백이 열렸으며, `%TEMP%` 는
     `Packages\...\LocalCache\` 로 옮겨지지 않았다
   - **B. 실제 `.msix` 설치** — `makeappx` 로 싸서 `C:\Program Files\WindowsApps\` 에
     설치했다. 그 폴더는 실제로 **쓸 수 없었고**, 앱은 문서 폴더에 `backups\`·`logs\` 를
     만들었다. A 가 재현하지 못하던 단 하나가 이것이다
   - **서명 없이 설치하는 법**: `signtool` 로 서명하고 인증서를 신뢰 저장소에 넣는 대신,
     시험용 신원의 `Publisher` 뒤에 Windows 가 정해 둔 **서명되지 않은 네임스페이스**
     표시(`OID.2.25.311729368913984317654407730594956997722=1`)를 붙이고
     `Add-AppxPackage -AllowUnsigned` 로 넣는다. 관리자 권한도, 이 PC 의 신뢰 목록을
     더럽히는 일도 없다. 이 표시는 `packaging/identity.dev.json` 에만 있고 스토어에
     올리는 `identity.json` 에는 **절대 붙이지 않는다** — 거기서는 Microsoft 가 서명한다
   - **`makeappx` 는 Windows SDK 를 통째로 깔지 않아도 된다**: NuGet 의
     `Microsoft.Windows.SDK.BuildTools` (21MB) 를 `tools\` 에 풀면 된다.
     `scripts/make_msix.py` 가 그 자리도 뒤진다
3. **제어된 폴더 액세스에 걸리면 판이 올라갈 때마다 다시 걸린다** `[확인됨, 미해결]`
   Windows 보안의 랜섬웨어 방지가 켜져 있으면 우리 앱은 문서 폴더에 쓸 수 없어
   `ensure_ready()` 가 시작을 막는다(그래서 오류 문구가 이것을 짚는다). 문제는 허용
   목록이 **exe 경로 단위**라는 것이다 — MSIX 설치 경로에는 판 번호가 들어가므로
   (`...\HomeSpread_1.0.19.0_x64__cx182f...\`) 판을 올리면 경로가 바뀌어 허용이 풀린다.
   사용자는 갱신할 때마다 다시 허용해야 한다. 우리가 코드로 고칠 수 있는 것이 아니고,
   기본값이 꺼져 있어 겪는 사람이 많지는 않다. **알고 내보내는 것과 모르고 내보내는
   것은 다르므로 여기 적어 둔다.**

   > **갱신 자체는 걱정할 것이 없다(2026-08-26 확인).** 1.0.19 를 깔아 둔 채로 1.0.20 을
   > 그대로 설치했더니 옛 판은 **자동으로 등록이 풀리고** 새 판만 남았다 — 판이 쌓이지
   > 않는다. 바로가기도 경로가 아니라 **패키지 신원**(`…_cx182f…!App`, 판 번호가 없다)을
   > 가리키므로 그대로 새 판을 띄웠다. 즉 폴더 이름이 바뀌는 것을 사용자가 볼 일은 없고,
   > 영향은 오직 Defender 허용 목록 하나뿐이다.
   >
   > 딸린 사실 하나: 옛 판의 **파일 폴더**는 등록이 풀린 뒤에도 한동안 디스크에 남는다
   > (164MB, 되돌릴 자리로 남겨 두고 Windows 가 나중에 치운다). 갱신 직후에는 차지하는
   > 공간이 잠깐 두 배가 된다.
4. **다른 기기·iOS 판에서 한 번 더 왕복** — 지금 확인된 것은 iPhone 14 / iOS 26.1 하나뿐이다
