## 2. Windows 分发方式比较

2026-08-21，上游已从单文件改为目录分发（`onedir`），输出 `dist\HomeSpread\`。MSIX 封装文件集合，而非只包装一个 exe；这也使当时测得启动时间由 21 秒降至 2.3 秒。

当时 Partner Center 的“新增产品”将应用分为 **MSIX 或 PWA 应用**、**EXE 或 MSI 应用**。另外的 `GDK game` 和“MSIX 或 PWA 游戏”属于游戏分类，不用于本项目。类别在创建产品时选择。

| 项目 | MSIX 或 PWA 应用 | EXE 或 MSI 应用（原政策 10.2.9） |
|---|---|---|
| 用户体验 | 商店安装并更新 | 商店使用开发者提供的安装文件 URL |
| 签名 | 商店分发阶段使用 Microsoft 签名；原方案无需采购用于该步骤的 CA 证书、PFX 或 USB 令牌 `[已核对]` | 原方案要求开发者自行进行 Authenticode 签名；商店不替 EXE/MSI 重新签名 `[已核对]` |
| 托管 | Microsoft CDN | 开发者基础设施或 CDN；每版使用独立、发布后不变的制品 URL |
| 更新 | 由商店处理 | 每版向 Partner Center 登记新的版本 URL |
| 需生成的内容 | `AppxManifest.xml` 与 `makeappx` 包 | 静默安装器，原规则仅允许 UAC 交互；离线完整安装，安装时不再下载其它组件 |
| 原评估风险 | 回环和路径写入风险已在 2026-08-26 的 A/B 测试中得到该环境验证；受控文件夹访问仍有问题 | 开发者承担签名、托管和更新维护成本 |

**上游选择了 MSIX 或 PWA 应用。**原决策的重要因素是签名职责和可验证的运行限制。当时计划先做第 4 节的 A/B 测试，若失败再评估 EXE/MSI；随后测试通过，因此该备选没有成为执行中的迁移计划。目录产物可作为两者输入，但 EXE/MSI 还需要 Inno Setup 等单独安装器。

### Windows 数据目录验证

2026-08-21 记录中，`C:\Program Files\WindowsApps\` 的所有者为 `NT AUTHORITY\SYSTEM`，该环境的管理员也不能直接写入。因此 `paths.data_root()` 在封装安装下使用用户文档目录中的 `HomeSpread`，而非安装目录。

原调查认为 `%LOCALAPPDATA%` 在封装应用中可能映射到 `Packages\...\LocalCache\`，会使备份位置难以找到。封装判断同时使用 `GetCurrentPackageFamilyName` 与 `is_frozen()`，避免把商店安装的开发用 Python 错认为应用包。图标缓存使用 `%TEMP%`。

2026-08-26 安装真实未签名测试 MSIX 后，确认安装目录不可写，`backups\` 和 `logs\` 创建于文档目录，图标位于 `%TEMP%\HomeSpread-cache`。该次观察未发现应用数据落入 `Packages\...\LocalCache\`，其中只有 Windows 自建结构 `[已核对]`。

**macOS 不采用这套目录规则。**当前中文版本使用用户 Application Support 保存备份、日志、设置和私有配对资料，Caches 保存图标；`.app` 内不写用户数据。

### 截图导致拒绝：2026-08-29，1.0.22

### 4.3 受控文件夹访问：上游已确认的剩余问题

启用 Windows 防勒索的受控文件夹访问时，应用可能不能写文档目录，`ensure_ready()` 会阻止启动并提示该原因。允许列表按 exe 路径记录，而 MSIX 安装路径带版本号，如 `...\HomeSpread_1.0.19.0_x64__cx182f...\`，升级后路径变化可能要求用户重新允许。原记录未在代码中解决此限制；它不适用于当前 macOS 路径。

2026-08-26 的更新实验：在 1.0.19 上安装 1.0.20 后，旧版自动取消注册，只保留新版注册；快捷方式引用不带版本号的包身份 `…_cx182f…!App`，因此能启动新版。旧版约 164 MB 的文件目录在取消注册后短暂保留供回退，之后由 Windows 清理，更新后空间占用可能暂时加倍。这是当时观察结果，不推断所有 Windows 更新配置都相同。

### 4.4 其它设备与 iOS

原上游实际写入证据仅覆盖 iPhone 14 / iOS 26.1。其它版本必须独立核验，不能因采用相同接口就认定兼容。本次 Mac 上的只读及备份成功不满足真实写入验证条件；任何写入测试都需展示具体动作和副作用并由用户明确确认。
