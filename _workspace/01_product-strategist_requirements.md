# 需求规格——HomeSpread

本规格保留原项目名 `iPhoneScreenManager` 时建立的需求编号，并按 2026-11-13 的 macOS 中文移植版校订。原可行性调查确认库中存在 `setIconState` 直接写入路径，随后重写了基于手势重放的需求。上游曾在 iPhone 14 / iOS 26.1 完成写入实测；本机完成的是 USB 读取和备份验证，不能套用上游写入结论。

## 优先级

- **P0：**设备验证和安全门禁，决定普通编辑能否写入。
- **MVP：**用户在桌面查看、编辑并经确认应用布局所需的功能。
- **条件性扩展：**未安排实现；只有明确出现相应需求或触发条件时才评估。

## P0——验证门禁

### REQ-001 设备连接和诊断

- **用户价值：**连接失败时知道下一步该做什么。
- **验收标准：**自动发现 USB 连接的 iPhone。只有一台时可自动选择；多台时要求断开其它设备或通过诊断参数明确指定，不默认选第一台、不回退 Wi-Fi。区分连接组件不可用、未信任、锁定和未连接，并给出操作提示。macOS 提示 Finder 与系统服务，Windows 提示 Apple Devices/iTunes。
- **优先级：**P0。

### REQ-002 查询布局

- **验收标准：**通过 `getIconState` 读取整份可返回的主屏幕布局，包括页面、文件夹和程序坞，获取标识符及显示名称，并保存原始结果。优先使用 `displayIdentifier`；不假定每个应用都含 `bundleIdentifier`，也不推断未返回的系统状态已经受到保护。
- **优先级：**P0。

### REQ-003 原样回写兼容性测试

- **用户价值：**在应用编辑前验证当前设备会话的写入路径，并明确暴露测试本身的真实写入影响。
- **验收标准：**读取当前 iconState → 经用户确认，将未编辑状态原样回写 → 再读取比较。测试前完成同设备备份和完整性校验；比较检查丢失、意外位移、内容变化，并单独报告新增条目。App 资源库回填不视作条目丢失，但必须提前警告，它无法通过恢复备份消除。
- **依赖约束：**普通编辑的“应用”要求本次会话 `write_verified` 为真。正常流程通过原样回写测试建立该标记；明确确认的恢复成功且读回比较安全，也会建立或刷新该标记。重新加载或失败后标记失效。界面和工作线程均执行门禁。读取不会自动触发测试。**恢复不受此门禁阻断**，以便在失败后使用同设备备份；恢复仍需归属验证、再次备份、明确确认和写后比较，不自动执行。
- **优先级：**P0。

### REQ-004 诊断日志文件——原始用户要求

- **用户价值：**实机出现问题时，有证据定位原因并改进实现。
- **验收标准：**
  - 每个会话写入独立的 `logs/<名称>_<YYYYMMDD_HHMMSS>_<微秒>_<随机后缀>.log`，不混写或覆盖。
  - 记录应用/库版本、操作系统/Python 版本、设备型号/iOS 版本、脱敏标识、服务连接结果、SpringBoard 命令及耗时/结果摘要、异常调用栈和用户编辑/应用/撤销操作。依赖库调试级输出关闭。
  - 原始 iconState 与网格参数另存于该会话的产物目录；日志正文保留路径和摘要。没有产物时不创建空目录。
  - 提供整会话 ZIP 导出。日志按保留规则清理，备份不自动删除。
  - 数据目录权限 0700，日志/备份/诊断文件权限 0600。UDID 仅保留前四字符；不主动记录电话、账户或完整序列号。设备名称、应用清单、文件夹名称和网页快捷方式 URL 仍可能出现，导出文件不是匿名数据。
- **优先级：**P0。

### REQ-005 查询网格参数

- **验收标准：**查询并记录 `getHomeScreenIconMetrics`。参数缺失或不可解释时明确记录，使用模型中声明的 iPhone 回退值；不把回退值称为本机实测，也不声称实现会根据页面结构推断列数。
- **优先级：**P0。

## MVP

### REQ-010 自动备份

- **用户价值：**保留写入前的布局，作为恢复依据。
- **验收标准：**每次写入前重新读取当前布局，在 `backups/<设备摘要>/` 下创建唯一命名的二进制 plist、可读 JSON 和归属/完整性元数据。数据持久化后重新读取校验。**备份失败即停止写入。**普通编辑还必须与用户读入时的原始快照比较，发现手机端变化则停止。备份不是整机备份，不能保证所有系统效果都能恢复。
- **优先级：**MVP。

### REQ-011 从备份恢复

- **验收标准：**展示当前设备的有效备份。恢复前核对文件所属设备、所在目录、元数据和内容摘要，再备份当前状态；用户明确确认后写入，随后重新读取比较。无可靠归属信息的旧文件允许预览，不直接恢复。兼容性测试失败后仍保留此明确确认的恢复入口；恢复成功且读回比较安全时，更新本次会话的编辑许可标记。
- **优先级：**MVP。

### REQ-012 同时显示多个页面

- **用户价值：**在电脑上查看手机无法同时展示的全部页面结构。
- **验收标准：**同屏展示页面和程序坞，提供缩放及“全部显示”。原需求以十页无需滚动仍能看到结构为目标；可读性取决于窗口大小，超出可视范围允许滚动。图标可显示真实 PNG 与名称，尚未下载或无法取得图标时显示文字替代块。
- **优先级：**MVP。

### REQ-013 拖动编辑

- **验收标准：**支持页面内/跨页移动、移入移出程序坞、移入移出文件夹，以及调整页面顺序。模型统一判断合法性，不允许未知项或空占位被编辑间接移走。
- **优先级：**MVP。

### REQ-014 撤销与重做

- **验收标准：**支持撤销和重做编辑。一次拖动及其连带的跨页顺移、页面创建或空文件夹清理构成一个撤销单位。
- **优先级：**MVP。

### REQ-015 变更预览和应用

- **验收标准：**应用前展示移动的应用、文件夹变化和页面变化，说明整份替换、自动备份、资源库回填及连接要求。用户勾选确认后才能继续。写前验证设备、快照和条目完整性，写后重新读取，报告丢失、意外位移、内容变化及新增项。
- **优先级：**MVP。

### REQ-016 显示未应用的更改

- **验收标准：**区分本地编辑和已写入状态，持续展示未应用变更数量；退出或重新读取会丢弃编辑时提示用户。
- **优先级：**MVP。

### REQ-017 保留未知项

- **用户价值：**避免将应用尚未理解的小组件、系统条目或新 iOS 字段静默丢弃。
- **验收标准：**原样保留未解释的数据，界面显示“未知项目”并禁用移动；普通编辑写入前还需验证这些条目的位置及原始值未改变。不支持的容器结构拒绝写入。
- **依赖约束：**`setIconState` 替换整份布局。原始数据保留是必要保护，但不能证明 Apple 未返回的状态可恢复，也不能从某个型号的成功推断其它 iOS 安全。
- **优先级：**MVP。

## 条件性扩展

### REQ-020 保存/载入编辑布局

将编辑结果保存为可再次使用的布局文件，并明确报告目标设备缺少的应用。当前可打开备份预览；跨设备应用布局不是已实现能力。只有用户提出该需求后才设计导入和映射规则。

### REQ-021 自动整理建议

按使用情况收集应用、按分类建议文件夹等。属于未安排的产品研究，不影响手动编辑路径验收。

### REQ-022 多设备配置

设备备份隔离已作为安全要求实现；多设备切换界面、命名配置和跨设备布局管理仍是条件性扩展，不能与已有隔离能力混淆。

### REQ-023 手势备用路径

仅在 REQ-003 失败、直接写入不适用且用户明确选择进一步研究时评估。`layout-diff-planner` 中的历史方案可作为研究输入，不自动执行 WDA 或设备手势。

## 不在范围内

- 实时屏幕镜像或远程控制。
- 安装、卸载应用。
- 越狱设备专属能力。
- Linux 运行支持。原始规格排除了 macOS；该条已由本次明确要求的 macOS 移植取代。
