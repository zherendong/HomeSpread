# 요구사항 명세 — iPhoneScreenManager

**전제 변경**: 타당성 조사 결과 `setIconState`로 레이아웃을 **직접 쓸 수 있음**이 확인되어(`[미검증]` 실기기 확인 대기), 제스처 재생 기반 요구사항을 전면 재작성했다.

## 우선순위

- **P0**: 실기기 검증 게이트. 이것이 통과해야 나머지가 의미를 가진다
- **MVP**: 사용자가 실제로 홈화면을 편집해 반영할 수 있는 최소 집합
- **후속**: MVP 이후

---

## P0 — 검증 게이트

### REQ-001 기기 연결과 진단
- **사용자 가치**: 연결이 안 될 때 무엇을 해야 하는지 안다
- **수용 기준**: USB로 연결된 iPhone을 자동 탐지한다. 실패 시 원인(드라이버 없음 / 미신뢰 / 잠김 / 미연결)을 구분해 다음 행동과 함께 표시한다
- **우선순위**: P0

### REQ-002 레이아웃 조회
- **수용 기준**: `getIconState`로 전체 홈화면(페이지·폴더·독)을 조회하고, 번들 ID와 표시 이름을 얻는다. 결과 원본을 파일로 보존한다
- **우선순위**: P0

### REQ-003 항등 왕복 안전 시험
- **사용자 가치**: 되돌릴 수 없는 동작을 하기 전에, 쓰기 경로가 무해하게 동작하는지 확인한다
- **수용 기준**: 현재 iconState를 조회 → **아무것도 바꾸지 않고** 그대로 `setIconState` → 재조회하여 조회 결과가 동일함을 확인한다. 셋 중 어느 단계라도 실패하면 그 사실을 명확히 기록하고 **쓰기 기능 전체를 비활성화한다**
- **의존 제약**: 이 시험 통과 전에는 어떤 변경도 기기에 쓰지 않는다
- **우선순위**: P0

### REQ-004 진단 로그 파일  ← **사용자 요청**
- **사용자 가치**: 실기기에서 문제가 생겼을 때 원인을 추적하고, 개선 사항을 발굴할 근거가 남는다
- **수용 기준**:
  - 모든 세션이 `logs/session_{YYYYMMDD_HHMMSS}.log`에 기록된다
  - 기록 항목: 앱/라이브러리 버전, OS·Python 버전, 기기 정보(모델·iOS 버전·UDID **일부 마스킹**), 서비스 연결 성공/실패, 모든 SpringBoard 명령의 호출·소요시간·결과 요약, 예외의 전체 스택트레이스, 사용자 동작(편집·적용·취소)
  - 기기에서 받은 **원본 iconState / 메트릭은 별도 파일**(`logs/artifacts/`)로 저장하고, 로그에는 파일 경로와 요약만 남긴다
  - 로그는 **덮어쓰지 않는다.** 세션마다 새 파일
  - 문제 신고용으로 **한 세션 전체를 zip으로 내보내는 기능**을 제공한다
  - 개인정보 최소화: UDID·일련번호는 앞 4자리만, 전화번호·계정은 기록하지 않는다
- **우선순위**: P0

### REQ-005 그리드 메트릭 조회
- **수용 기준**: `getHomeScreenIconMetrics` 결과를 조회·기록한다. 값이 없거나 해석 불가하면 그 사실을 기록하고 조회 결과의 페이지 구조에서 열 수를 추정한다
- **우선순위**: P0

## MVP

### REQ-010 자동 백업
- **사용자 가치**: 무엇이 잘못되어도 원래대로 돌아갈 수 있다
- **수용 기준**: 쓰기 직전에 항상 현재 iconState를 `backups/{기기}_{시각}.plist`로 저장한다. **백업 저장에 실패하면 쓰기를 수행하지 않는다**
- **우선순위**: MVP

### REQ-011 백업으로 복원
- **수용 기준**: 저장된 백업 목록을 보여주고, 선택한 백업을 그대로 기기에 적용한다. 복원 직전에도 현재 상태를 백업한다
- **우선순위**: MVP

### REQ-012 다중 페이지 동시 표시
- **사용자 가치**: 이 앱의 존재 이유. iPhone에서는 한 번에 한 페이지만 보인다
- **수용 기준**: 모든 홈화면 페이지와 독을 한 화면에 동시에 표시한다. 페이지가 10개여도 스크롤 없이 전체 구조가 보인다. 각 아이콘은 실제 앱 아이콘 이미지와 이름으로 표시된다
- **우선순위**: MVP

### REQ-013 드래그 편집
- **수용 기준**: 아이콘을 페이지 간·페이지 내에서 드래그로 옮긴다. 독에 넣고 뺀다. 폴더 안팎으로 옮긴다. 페이지 순서를 바꾼다
- **우선순위**: MVP

### REQ-014 실행 취소
- **수용 기준**: 편집 동작을 되돌리고 다시 실행한다. 드래그 1회 = 취소 단위
- **우선순위**: MVP

### REQ-015 변경 미리보기와 적용
- **수용 기준**: 적용 전에 무엇이 바뀌는지(이동한 앱 목록, 폴더 변화, 페이지 변화)를 보여준다. 사용자가 확인해야 적용된다. 적용 후 재조회하여 의도한 결과가 됐는지 대조하고 결과를 보고한다
- **우선순위**: MVP

### REQ-016 미적용 변경 표시
- **수용 기준**: 편집했으나 기기에 반영되지 않은 상태를 시각적으로 구분하고, 미적용 변경 수를 항상 표시한다. 미적용 상태로 종료 시 경고한다
- **우선순위**: MVP

### REQ-017 알 수 없는 항목 보존
- **사용자 가치**: 앱이 이해하지 못하는 항목(위젯, 시스템 항목, 새 iOS 기능)을 덮어쓰기로 삭제하지 않는다
- **수용 기준**: iconState의 해석하지 못한 요소를 **원형 그대로 보존**하여 다시 써넣는다. UI에는 "알 수 없는 항목"으로 표시하고 이동을 막는다
- **의존 제약**: setIconState는 전체 덮어쓰기이므로, 보존하지 않으면 사라진다. **MVP에서 가장 위험한 요구사항**
- **우선순위**: MVP

## 후속

### REQ-020 레이아웃 저장/불러오기
- 편집한 레이아웃을 파일로 저장하고 나중에 불러온다. 기기에 없는 앱은 명시적으로 보고한다

### REQ-021 자동 정리 제안
- 사용하지 않는 앱 모으기, 카테고리별 폴더 제안 등

### REQ-022 여러 기기 프로파일
- 기기별 백업·레이아웃 분리 관리

### REQ-023 제스처 폴백 경로
- REQ-003이 실패할 경우에만 착수. `layout-diff-planner` 스킬의 설계를 그대로 사용한다
