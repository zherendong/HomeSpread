# 小组件与 iPhone Duo 只读预览独立验收

日期：2026-11-13。版本：`1.0.22-mac.zh.2`。范围：小组件分类、原始布局保留、跨格预览、Duo 双页展示，以及全部手机写入入口的拒绝条件。

本次测试只使用自行构造的布局、临时目录和假设备。没有调用真实手机读取、真实手机写入或诊断 `--roundtrip`，没有把个人备份、应用清单或截图加入测试文件。

## 结果

**264 项测试通过，383 项子测试通过，0 项失败，测试进程退出码为 0。** 包含原有 173 项检查，以及本轮 19 项模型/占位检查、8 项界面检查、64 项独立写入策略、离线隔离与按钮交互检查。

Qt 拖放事件模拟使用的构造函数产生 1 条弃用警告；它来自测试用例，不影响本次测试结果。早期全量运行暴露了测试中无父对象 PageFrame 的清理问题：测试汇总后进程未能正常退出。界面测试改为明确持有并处理延迟删除后，独立模块与最终全量运行均正常退出，不能只以 pytest 已打印通过数量作为完成依据。

最终运行方式为使用项目虚拟环境，在隔离目录及 `QT_QPA_PLATFORM=offscreen` 环境下执行 `python -m pytest -q --tb=short`。外层进程设置 45 秒超时并传播 pytest 退出码；最后一次运行约 7 秒完成。结果文件为未纳入版本控制的 `build/widget-final-qa.log`。

## 已核验的边界

| 边界 | 结果 |
|---|---|
| 小组件与文件夹分类 | 单组件与堆叠在检查 `iconLists` 前被识别为 `WIDGET`；空 `iconLists` 不再把它们变成空文件夹。只有明确且结构有效的 `listType=folder` 才作为文件夹。 |
| 未知结构 | 含模糊容器、未知图标类型或不支持的数据保留为未知项；不能仅因有应用标识符就视为可编辑应用。 |
| 原始数据 | 组件未知字段、二进制值、堆叠成员及选中成员均完整保留；预览与序列化不改原始数据。布局备份仍可保存和完整读回含组件的布局。 |
| 小组件占位 | 中号组件 4×2，小号 2×2，大号 4×4。中号组件加 8 个普通项目占 16/24 格；加 16 个项目占 24/24 格。 |
| 未知尺寸与溢出 | 不猜测未知组件尺寸；将无法定位的项目明确列在提示中，不静默丢弃或剪裁。原始条目索引仍保持关联。 |
| 小组件计数 | 3 个组件位置，其中 1 个含 7 项的堆叠、2 个独立组件，得到 3 个组件位置与 9 个组件成员；堆叠成员不计入 App 或文件夹。 |
| Duo 展示 | 将原有逻辑页面成对展示，并把程序坞显示在每对页面右侧；奇数末页只显示无下一页提示，不往原始布局插入空页。 |
| 只读交互 | 组件/未知布局和 Duo 预览禁用拖放、分组、重命名、增删/重排页面与全部手机写入。文件夹仍可打开查看。 |
| 显示模式切换 | 真实设备信息为 `iPhone19,4` 时，切回普通逐页视图也不能获得写入许可；旧的或人为设置的通过标记不能绕过策略。 |
| 离线入口 | 打开备份的窗口不查询 USB 服务就绪状态；离线工作线程在创建设备连接前拒绝连接。打开预览不会加载手机或下载图标。 |
| 写入前保护 | `guarded_write` 检查目标、读入基线和设备当前状态。组件、堆叠、未知项、占位或 Duo 都会在实际写入前被拒绝。 |
| 恢复与校验旁路 | 即使备份设备归属和摘要正确，组件/Duo 布局仍不能通过恢复或原样校验写入；更换 reason 参数不能绕过。 |
| 最低层保护 | `DeviceBridge.set_icon_state` 检查已读取状态、目标状态及设备型号，在不支持时连 SpringBoard 写入服务都不会打开。 |
| 写后比较 | 同一组件标识符下的堆叠成员、选中成员、未知内容或 `iconLists` 变化都能被比较器识别为不安全；不把组件字段当文件夹子项过滤掉。 |
| CLI 路径 | 静态检查诊断和实机验证脚本没有直接 `set_icon_state` 调用，均经过统一保护。未执行这些真实设备脚本。 |

## 旧测试的必要调整

原 `SAMPLE` 包含一个无法理解的组件样本，却被多数普通移动/分组测试作为可编辑布局复用。新策略要求整份未知布局只读，因此普通编辑测试改用移除该未知项的独立 `EDITABLE_SAMPLE`；原 `SAMPLE` 保留用于解析、备份、未知项保留和拒绝编辑验证。没有跳过或删除原来的未知项安全断言。

版本断言更新为本轮版本。原来的成功拖放和未知项拒绝使用两个独立文档，分别验证支持布局可编辑、不支持布局不可编辑。测试结果不依赖真实手机数据。

## 发现与修复

1. 原分类逻辑会把含空 `iconLists` 的组件误认成可移动空文件夹；原条目保留检查因此可能忽略它们。新类型与独立写入策略共同修复。
2. 原画布按每项目一格绘制，无法表达组件占位。新的纯占位模型和界面命中测试共同验证跨格矩形与后续图标位置。
3. 仅在编辑时阻止写入不够：恢复可以把带组件的当前布局覆盖成无组件旧布局。现在对当前和目标都检查，恢复不再是支持能力限制的旁路。
4. 仅禁用界面按钮不够：工作线程、统一写入入口和设备桥均有拒绝保护，并用假设备断言实际写入调用数为零。
5. 历史“校验失败仍保留恢复”约定只适用于受支持的设备与布局。不支持组件/Duo 的能力限制优先，不能借“恢复”执行未经适配的整体写入。

## 验证范围与限制

本轮独立 QA 验证的是源代码、模拟设备边界及离屏 Qt 界面。主任务另行对已有本地备份进行只读预览比对；个人原始数据不属于本报告附件。

预览使用接口条目顺序与已知组件尺寸进行确定性排布，不声称能还原接口未提供的自由摆放位置、系统全部状态或组件实时画面。组件卡片显示尺寸与堆叠数量，不伪造天气、活动或其它实时数据。

**Duo、组件及未知布局仍禁止手机写入。** 本轮不验证折叠/展开后的真实写回、恢复、断线写入或系统兼容性。源码测试通过不能推导这些能力已经可用。最终应用包的签名、内置源码一致性与安装启动由主任务单独核验。

## 应用包补充核验

主任务生成的 `mac.zh.2` Apple Silicon 应用包已通过 `codesign --verify --deep --strict`，并使用 `--preview`、`--profile duo`、`--smoke-test` 离线启动、绘图和正常退出。已对授权的本地备份检查 SHA-256 未变化，模型导出的二进制 plist 与备份逐字节一致；私有图像只保存在忽略的构建目录，不随源码或报告分发。

内置源码包逐项与工作区核对一致，未含设备备份、日志、配对记录、用户图标缓存或虚拟环境。该检查不证明真实写回兼容性，手机写入仍禁用。

原生验收中发现模式下拉框触发 Qt Cocoa 无障碍弹出菜单崩溃，模式选择改为两个互斥按钮。另补充 checked-state 激活回归：无障碍操作可能只改变选中状态，不发出鼠标 clicked 信号，因此使用 toggled 驱动实际排版，避免按钮外观与画布模式不一致。该回归检查原始布局不变和所有写入入口持续禁用。
