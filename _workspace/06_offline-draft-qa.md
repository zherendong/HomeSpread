# 离线草稿编辑：独立验收记录

日期：2026-11-13。范围：`mac.zh.3` 离线草稿模型、专用文件格式、界面操作与设备写入隔离。测试使用虚构的 `example.*` 应用、小组件、堆叠、日期和二进制字段，没有读取或操作真实手机，也没有使用个人备份作为公开测试样本。

## 结果

**431 项测试、439 项子测试通过，0 项失败，进程退出码 0。** 完整测试在 45 秒子进程超时保护下执行，实际用时 8.48 秒。唯一警告来自既有 `QDragEnterEvent` 测试构造器弃用提示；没有测试跳过或 Qt 退出挂起。

相对上一阶段的 371 项测试，新增 60 项：13 项草稿核心测试、9 项界面测试及 38 项独立边界检查。完整命令如下，在仓库根目录执行：

```sh
QT_QPA_PLATFORM=offscreen \
HOMESPREAD_DATA_DIR="$PWD/build/draft-qa-data" \
HOMESPREAD_CACHE_DIR="$PWD/build/draft-qa-cache" \
.venv/bin/python -m pytest -q
```

## 核心边界

| 边界 | 验收结果 |
|---|---|
| 允许的编辑 | 仍只允许同一逻辑页中两个普通 1×1 App 的完整对象互换。Dock、组件、文件夹、文件夹内应用及跨页交换不开放。 |
| 基线与草稿分离 | `OfflineDraft.origin`、`current_state` 和 `current` 返回独立快照；调用者修改返回对象不会污染基线或内部历史。 |
| 连续编辑 | 多次交换形成独立历史，撤销/重做恢复相应快照；撤销后新建操作会替换旧重做分支。 |
| 已保存状态 | `dirty` 比较当前状态和上次成功保存状态，`has_changes` 比较当前状态和原始基线；两者不会混用。逆向交换回到原始布局仍可能有未保存状态，界面按 `dirty` 提醒。 |
| 原始数据保留 | 原始备份文件字节不变。组件原文、堆叠成员/顺序/选中项、建议开关、文件夹内容、日期微秒、不透明字节及布尔类型均保留。 |
| 差异展示 | 按原始位置比较最终状态，报告两个指定 App 的前后名称；不把操作次数误当作最终差异数。 |
| 文件格式 | `.hsdraft` 是包含格式标识、版本、离线用途、禁止写设备标记、原始/当前布局、摘要及操作序列的二进制 plist 字典；它不是原始布局备份。 |
| 读入验证 | 读取文件有 32 MiB 上限，要求已知格式及严格类型，重放每个操作后比较完整当前状态与摘要；截断、错误版本、伪造摘要、布尔索引和超限历史被拒绝。 |
| 不能靠重算摘要绕过 | 篡改组件选中项、布尔值、第三个应用、Dock 或文件夹，即使重新计算当前布局摘要，也无法通过操作重放验证。 |
| 不能误恢复到手机 | `.hsdraft` 改名为 `.plist` 后仍被备份读取层拒绝；即使另造符合当前设备和 SHA-256 的备份元数据，`restore()` 仍在任何假设备读取/写入前拒绝字典草稿。 |
| 文件保存 | 只允许 `.hsdraft`；原始 `.plist` 或只是改成草稿扩展名的原始备份不能被覆盖。新文件为私有 0600 权限，使用原子写入并读回比较。 |
| 保存失败 | 磁盘写入失败不会清除 `dirty` 或标记成功保存。输入未包含后缀时，补成现有 `.hsdraft` 文件必须单独取得覆盖确认，拒绝时旧文件与草稿均保留。 |

保存只持久化当前有效操作序列，不保存已撤销的重做尾部。重新打开已保存草稿可以撤销其中已保存的步骤，加载后的状态为未修改。

摘要和操作重放用于完整性及操作范围检查，不是数字签名，不能证明任意外部文件的作者或设备归属。任何通过检查的草稿也不获得设备写入许可。

## 界面与设备隔离

独立界面测试将 USB 准备检查、Python socket、设备桥工厂以及工作线程的读取、图标下载、应用、原样写回和恢复方法替换成“调用即失败”的对象，再执行实际界面数据流程。

已验证：

- 从本地备份开始草稿，选择两个 App、交换、查看原始/草稿、撤销/重做、保存和重开，均没有触发设备或网络入口。
- 切回逐页预览、伪造 `write_verified=True` 或伪造普通机型/连接状态，都不能在草稿模式启用设备读取、图标下载、应用、恢复或原样写回；直接调用相关界面处理函数同样被阻止。
- 原始布局视图不能选择并交换 App；点击小组件、文件夹、Dock、文件夹内应用或另一页应用，不会改变草稿。
- 原始/草稿切换按钮使用选中状态事件驱动实际画布，验证了无障碍激活场景，而不仅是鼠标 `clicked` 信号。
- 取消关闭、打开另一份备份/草稿或退出草稿，会保留当前未保存草稿；选择保存后又取消保存对话框，也不会继续关闭。
- 打开损坏草稿会保留已有未保存会话；验证新文件在丢弃旧会话之前执行。
- 替换的页面、Dock 与文件夹控件在延迟销毁前先隐藏，避免已移除 Dock 短暂覆盖新画布。

上述检查使用离屏 Qt 及合成数据。原生 macOS 点击、打包、签名与安装后的实际界面由主任务单独验收，不计入这些自动测试。

## 源码与研究模块

既有纯研究规划器已提升为 `src/ipsm/draft_rules.py`，研究模块只重导出这一个实现，避免两套规则分叉。研究隔离测试没有放开任意生产导入：它仅允许这一重导出，并同时审查规则模块、包初始化、版本和产品常量的导入链，拒绝设备、网络、GUI及动态执行依赖。

草稿持久化层只依赖纯规则、翻译和本地安全文件写入，不依赖设备工作线程。生产 `write_policy.py`、设备桥、受保护写入和恢复实现未在本阶段放宽。Duo 和组件的真实写回限制继续生效。

## 发现与处理

1. 首轮完整回归只有两个新覆盖提示缺少中英文目录，补齐后完整通过；没有以跳过翻译测试代替修复。
2. 版本断言按本轮 `mac.zh.3` 更新；没有删除原版本格式要求。
3. 新增 `tests/conftest.py` 统一测试导入路径，使研究测试可单独运行；它不启动应用或设备线程。
4. 新增文件后缀补齐覆盖确认回归，以及伪造备份元数据仍不能恢复草稿的反例，覆盖原有常规成功路径之外的边界。

## 未验证与明确限制

本轮没有连接、读取或写入手机，没有运行真实 `--roundtrip`。草稿中的几何仍基于已知 4×6 逻辑页面模型，不能证明手机的任意空隙、隐藏页、组件实时配置或折叠状态都可由协议完整保留。

本阶段提供的是电脑上的离线规划和保存能力，不提供把该草稿发送到 Duo 的入口。原始备份与 `.hsdraft` 均可能包含应用名称、标识符、文件夹和布局，应保留在本地；不能将“草稿未写手机”解释成文件不含个人信息。
