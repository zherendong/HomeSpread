# ADR-001 — 데스크톱 UI 스택

**상태:** 채택 · 2026-08-20
**결정자:** 하네스 (사용자 승인 대기 없이 진행, 되돌릴 수 있는 결정)

## 맥락

Phase 1~2 에서 확정된 조건:

- 기기 통신 계층은 **pymobiledevice3** 이며 순수 Python, 전면 async 다. 이것은 바꿀 수 없다 —
  `com.apple.springboardservices` 를 이 라이브러리 말고 붙일 현실적 대안이 없다.
- 화면의 본질은 **아이콘 300여 개를 한 화면에 펼치고 드래그로 옮기는 캔버스**다. 표도 아니고
  문서도 아니다.
- 대상은 **Windows 전용**, 비개발자 사용자. 설치가 어려우면 쓰이지 않는다.
- 실기기 검증 결과 그리드는 4×6, 페이지 6개, 폴더 26개, 항목 309개다. 앞으로 더 늘 수 있다.

## 검토한 선택지

| 후보 | 유리한 점 | 불리한 점 |
|------|----------|----------|
| **PySide6 (Qt)** | Python 그대로 — 기기 계층과 한 프로세스. `QGraphicsView` 가 수백 개 타일의 드래그·확대를 감당한다. LGPL 이라 배포 가능. `qasync` 로 async 통합 | 설치 용량이 크다 (~80MB) |
| Tkinter | 표준 라이브러리, 설치 불필요 | 드래그앤드롭 캔버스를 처음부터 만들어야 한다. HiDPI 가 약하다 |
| Electron / Tauri + 웹 UI | UI 자유도 최고 | **프로세스가 갈린다.** 기기 계층(Python)과 UI 사이에 IPC 를 만들어야 하고, 그 경계가 곧 새 결함면이다 |
| WinUI 3 / WPF (C#) | Windows 네이티브 | pymobiledevice3 를 못 쓴다. 기기 계층을 통째로 다시 만들어야 한다 |

## 결정

**PySide6 (Qt for Python, LGPLv3)** 를 채택한다. `PySide6-Essentials` 만 설치한다
(전체 패키지의 3D·Charts·WebEngine 은 쓰지 않는다).

결정을 가른 것은 **프로세스 경계**다. 이 프로젝트에서 가장 위험한 일은 기기에 쓸 상태가
어디선가 조금 달라지는 것이다(REQ-017). UI 와 기기 계층이 한 프로세스 안에서 **같은 Python
객체**를 주고받으면, 편집한 것과 기기에 쓰는 것이 같은 객체임을 자료 구조가 보장한다.
IPC 를 끼우면 그 경계마다 직렬화가 생기고, 직렬화는 우리가 모르는 키를 잃는 지점이다.
웹 UI 의 자유도는 그 위험을 살 만큼 크지 않다.

라이선스: PySide6 는 LGPLv3, pymobiledevice3 는 GPL-3.0-or-later. 배포물 전체는
**GPL-3.0-or-later** 로 나간다 — pymobiledevice3 쪽이 더 강하므로 그 조건이 전체를 지배한다.
소스를 공개하는 프로젝트이므로 문제되지 않는다.

## 결과로 따라오는 것

- **async 통합**: Qt 이벤트 루프와 asyncio 를 함께 돌려야 한다. `qasync` 를 쓰지 않고,
  기기 작업을 **`QThread` 위의 독립 이벤트 루프**에서 돌린 뒤 시그널로 결과만 넘긴다.
  이유: 의존성이 하나 줄고, 무엇보다 기기 작업 도중 UI 가 멈추지 않는다는 것이 눈으로
  확인된다. 쓰기 도중 UI 가 얼어붙으면 사용자가 케이블을 뽑는다.
- **패키징**: PyInstaller 1파일 실행형. 다만 MVP 단계에서는 `run_app.bat` 로 실행한다 —
  패키징은 기능이 굳은 뒤에 한다.
- **DPI**: Qt 6 은 기본으로 DPI 를 따라간다. 아이콘 원본은 기기가 준 PNG(대개 120px 내외)
  이므로 확대해도 견딜 만하다.

## 되돌릴 수 있는가

있다. `layout.py`, `iconstate.py`, `device.py`, `backup.py`, `icons.py` 는 Qt 를 전혀
모르며 앞으로도 몰라야 한다. UI 를 통째로 갈아치워도 안전 규약과 모델은 그대로 남는다.
이 경계를 지키는 것이 이 ADR 의 실질적인 내용이다.
