# ADR-001——桌面界面技术栈

**状态：**已采用。原决定日期 2026-08-20；macOS 移植校订日期 2026-11-13。

**原决定方式：**项目开发流程内作出的可逆实现选择。

## 背景

原第 1～2 阶段明确的条件如下：

- 设备通信层采用 **pymobiledevice3**，Python 实现，所用接口全面异步。它是选定的实现，不是唯一理论选项；`libimobiledevice` 仍是需要额外绑定和分发工作的条件性替代。
- 核心界面是将约 300 个图标同时展示并允许拖动的画布，而非表格或文档编辑器。
- 原目标是面向非开发者的 Windows 应用；本次工作增加 macOS 中文版本。安装和启动必须易用。
- 原上游实测环境具有 4×6 网格、6 个页面、26 个文件夹和 309 个条目。这些数字是该设备的历史样本，不是其它设备的固定规格。

## 比较过的方案

| 候选 | 优点 | 代价或限制 |
|------|----------|----------|
| **PySide6（Qt）** | 直接使用 Python，可与设备层同进程；`QGraphicsView` 等画布能力适合大量图标的拖动和缩放；可按 LGPL 条件分发；可选 `qasync` 集成 | 原评估安装体积约 80 MB，实际制品大小取决于版本和打包内容 |
| Tkinter | Python 标准库，通常无需单独安装 | 需要自行实现拖放画布；原评估认为 HiDPI 支持较弱 |
| Electron / Tauri + 网页界面 | 界面表现灵活 | 需要在 Python 设备层与界面之间建立 IPC，并维护额外的序列化边界 |
| WinUI 3 / WPF（C#） | Windows 原生界面 | 不能直接使用 Python 库，需要进程桥接或重写设备层；不适合本次 macOS 移植目标 |

## 决定

采用 **PySide6（Qt for Python，LGPLv3）**，只安装 `PySide6-Essentials`。应用不使用完整包中的 3D、Charts 或 WebEngine。

主要依据是减少进程和序列化边界。项目必须原样保留未知字段（REQ-017）；让界面、布局和设备层在同一 Python 进程内传递结构，可以减少重新构造数据时丢字段的机会。这是风险降低措施，不是对象永远不会被误改的保证。当前写入入口还会复制调用者数据，验证原始快照和条目完整性。

许可证安排：PySide6 使用 LGPLv3，pymobiledevice3 使用 GPL-3.0-or-later；项目整体按 **GPL-3.0-or-later** 分发，并提供对应源码、许可证和依赖告知。

## 由此形成的实现

- **异步集成：**不使用候选方案中的 `qasync`。设备任务运行在 `QThread` 内独立的 asyncio 事件循环上，通过 Qt 信号返回结果。这样减少一个依赖，并让设备读写不阻塞界面。写入期间界面可响应，有助于避免用户误判程序失去响应而拔掉数据线。
- **打包：**原 ADR 曾计划 PyInstaller 单文件可执行程序，并通过 `run_app.bat` 运行源码。后续 Windows 实测发现每次解包启动成本过高，改为目录分发；当前 Windows 规则见 `HomeSpread.spec`。macOS 使用 PyInstaller `.app` 应用包，用户数据位于 Application Support，不能写进应用包或临时解包目录。单文件打包是被取代的历史方案。
- **DPI：**Qt 6 默认支持显示缩放。图标使用设备提供的 PNG，原样本通常约 120 像素；不同设备的图标尺寸与缩放可读性应按实际界面检查。

## 可替换边界

`layout.py`、`iconstate.py`、`device.py`、`backup.py`、`icons.py` 不依赖 Qt。替换整个界面时仍可复用模型和安全规则。保持这一边界是本 ADR 的核心约束。

当前应用通过 USB 与设备通信。是否能安全写入某部手机由明确确认后的本次会话兼容性测试判断；技术栈选择本身不提供设备兼容性或完整恢复保证。
