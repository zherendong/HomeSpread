## 1. 确定尺寸

页面行列数、程序坞容量、文件夹容量和页数上限可能受设备、显示设置与 iOS 版本影响。不能凭记忆填写。

1. 优先检查目标设备返回的网格信息，并以实际布局确认含义。
2. 采用截图测量时，记录图标中心间距与测量条件；“已测量”不代表所有结构约束都得到验证。
3. 有可靠资料时标记“资料依据”并附来源。
4. 未验证就保留“未验证”，不得据此放行真实自动修改。

配置错误会导致容量判断或坐标错误，手势研究中还可能将图标拖到错误位置。

### 历史截图测量回退

1. 获得获准访问的主屏幕截图。
2. 检测重复的图标方形区域。
3. 用水平、垂直中心间距推断行列。
4. 单独识别底部程序坞区域与容量。
5. 将来源标为 `estimated`，保留测量证据。

上层必须知道它是推断结果。用户确认可帮助核对显示，但不能替代尚未证明的写入语义。

## 2. 空位规则

历史设计区分两种理想化模式：

| 模式 | 规则 | 可能影响 |
|------|------|----------|
| 连续填充 | 从左上角按序填充，不允许中间空位 | 移走一项可能使后续项前移 |
| 自由布局 | 允许特定空位 | 移动一项可能不压紧其他项，但仍需验证插入与顺延行为 |

连续填充可近似为有序列表，自由布局可表达为稀疏网格。这一区分影响历史手势规划，不能将实际 iOS 的全部规则简化为未验证的二选一。

若实现该扩展：

- 定义 `allowsGaps` 等能力字段及确切含义。
- 数据模型表达空位，再用不变量约束不允许空位的模式。
- 上层按能力工作，不到处根据版本号猜测。
- 每个值须在对应环境验证。

当前不支持的空位或小组件结构必须原样保留，不能自动压紧或改写。

## 3. 小组件表达

历史模型提出两种表达：

| 方式 | 优点 | 代价 |
|------|------|------|
| 锚点加尺寸 | 简洁，易表达移动 | 查询占用需要计算 |
| 占用位置集合 | 冲突检查直观 | 信息重复，移动时需同步全部位置 |

若确有需要实现可编辑小组件，建议以锚点加尺寸为唯一数据来源，按需派生占用集合，避免双份数据不同步。

候选字段：

- 锚点行、列。
- 占用行数、列数。
- 能可靠获知时的所属应用 bundle ID。
- 能可靠获知时的小组件类型标识。

无障碍树可能没有可靠标签。只知道尺寸而不知道身份时，历史方案提出 `unresolved` 标记并排除移动。当前实现更保守：未知原始结构保留内容和位置，不开放小组件编辑。

### 冲突检查

若该能力被正式实现，放下前检查：

- 锚点位于网格内。
- 锚点加尺寸不越界。
- 不与已有项目占用区域重叠。
- 尺寸在设备已验证的允许集合中。

界面调用模型检查，不能自行复制规则。

## 4. 文件夹约束

- 不允许文件夹包含文件夹，类型和操作检查均应体现。
- 文件夹含多个内部页面。
- 每页容量及最大页数由配置确定。
- 文件夹名称可能由系统生成，也可由用户修改。

### 历史手势成本

| 操作 | 若采用手势，需要的动作 |
|------|------------------------|
| 放入应用 | 拖到文件夹上 |
| 移出应用 | 打开 → 拖出 → 关闭 |
| 创建文件夹 | 将应用拖到另一应用上 |
| 解散文件夹 | 逐个移出内部应用 |
| 重命名 | 打开 → 编辑名称 → 确认 |

在手势方案中，解散的成本与项目数量相关，不能当成一次普通移动。详见 `../../layout-diff-planner/SKILL.md`。

当前布局编辑在内存中修改，最后整体写入，不执行上述手势；不能用手势成本预测当前应用耗时。

## 5. 程序坞

程序坞在模型中是独立容器：

- 容量与主页面不同。
- 在各主屏幕页面都显示相同内容。
- 文件夹支持范围按设备证据和模型约束处理。
- 不能未经验证允许小组件进入程序坞。

原始 iconState 的第 0 项表示程序坞，但这不意味着它与普通页面具有相同容量和规则。解析边界保留原始数组位置，编辑模型使用独立容器。

## 6. 发现配置错误

历史坐标提取中需要检查：

| 信号 | 可能原因 |
|------|----------|
| 两个项目映射到同一位置 | 行列估算不足、检测错误或坐标映射错误 |
| 项目越界 | 尺寸或原点错误 |
| 最后一行或列始终空白 | 可能高估尺寸，也可能是真实空位，不能单凭此项判定 |
| 程序坞项目落入页面 | 区域边界错误 |
| 图标数与识别位置数不同 | 漏检、重复检测或映射错误 |

位置冲突必须阻止自动规划，重新检查原始证据；不能仅显示警告后继续。当前模型则应测试容量、顺延、未知位置及序列化不变量。

## 7. 历史配置模式示例

以下为候选模式，英文枚举示意值便于跨语言使用，不是已发布文件格式：

```text
DeviceProfile
  id                 ：配置标识
  deviceModel        ：设备型号，已知时填写
  source             ："table" | "measured" | "estimated"
  verification       ："confirmed" | "documented" | "unverified"

  page.rows          ：整数
  page.columns       ：整数
  page.maxPages      ：整数
  dock.capacity      ：整数
  folder.perPage     ：整数
  folder.maxPages    ：整数

  capabilities.allowsGaps       ：bool
  capabilities.widgetSizes      ：允许尺寸集合
  capabilities.dockAllowsFolder ：bool
  capabilities.dockAllowsWidget ：bool

  slotOrigin         ："topLeft"
  slotOrder          ："rowMajor"
```

`source` 和 `verification` 是区分事实与推断所必需的信息。上层不能把推断配置当成已验证的写入前提。
