## 1. 파이프라인 단계

```
[1] 기기 프로파일 결정
     ↓
[2] 설치 앱 목록 조회  →  {번들 ID → 이름, 아이콘} 사전
     ↓
[3] 페이지 순회
     ├─ 구조 덤프 (접근성 트리)
     └─ 스크린샷
     ↓
[4] 좌표 → 슬롯 매핑
     ↓
[5] 앱 식별 (사전 조회 + 아이콘 매칭)
     ↓
[6] 교차 검증 + 신뢰도 산출
     ↓
[7] observed 레이아웃
```

### 단계별 원칙

**[1] 프로파일을 먼저 정한다.** 슬롯 매핑이 프로파일에 의존하므로 순서를 바꿀 수 없다. 프로파일이 미상이면 실측 폴백을 먼저 수행한다.

**[2] 앱 목록을 먼저 조회한다.** 화면을 읽기 전에 사전을 준비해야 식별 단계에서 다시 기기를 건드리지 않는다. 기기 접근 횟수를 줄이는 것은 신뢰도와 속도 양쪽에 이롭다.

**[3] 순회는 상태를 바꾸는 동작이다.** 절차와 함정은 `ios-device-protocol` 스킬의 `references/capture-and-structure.md` 참조. 이 파이프라인 관점에서 중요한 것은 **각 페이지의 원본 데이터를 보존**하는 것이다. 파싱에 실패해도 원본이 남아 있으면 나중에 재파싱할 수 있다.

**[4] 슬롯 매핑은 아이콘 이미지 영역 기준으로 한다.** 라벨 텍스트를 포함한 영역의 중심을 쓰면 행 판정이 아래로 밀린다.

**[5] 식별 실패는 정상이다.** 시스템 앱, 위젯, 테마 적용 아이콘은 실패할 수 있다. 실패를 예외로 던지지 말고 `Unknown`으로 흘려보낸다.

**[6] 검증 없이 결과를 내보내지 않는다.** 아래 3절 참조.

## 2. 부분 실패 처리

**3페이지까지 읽고 4페이지에서 실패했다면, 그 3페이지는 유효한 성과다.**

전체를 버리지 말고 다음을 반환한다:

```
ExtractionResult
  layout          : 읽어낸 부분까지의 레이아웃
  completeness    : "complete" | "partial"
  failedAt        : 실패 지점 (페이지 인덱스, 단계)
  failureReason   : 원인
  rawArtifacts    : 원본 덤프·스크린샷 경로
```

**`completeness`가 `partial`이면 하위 계층은 적용 계획을 세워서는 안 된다.** 읽지 못한 페이지에 무엇이 있는지 모르는 상태에서 이동을 계획하면, 읽지 못한 영역의 아이콘을 밀어낸다. 이 판단을 UI나 동기화 엔진에 맡기지 말고 결과 타입으로 강제하라.

## 3. 교차 검증

내보내기 전에 다음을 확인한다. 하나라도 걸리면 신뢰도를 낮추거나 실패로 처리한다.

| 검사 | 실패 시 의미 | 조치 |
|------|------------|------|
| 슬롯 충돌 (두 항목이 같은 슬롯) | 프로파일 오류 | **추출 실패 처리** + 실측 폴백 |
| 격자 범위 밖 슬롯 | 프로파일 또는 원점 오류 | 추출 실패 처리 |
| 트리 아이콘 수 ≠ 스크린샷 인식 수 | 인식 누락 또는 과다 | 신뢰도 하향 + 경보 |
| 번들 ID 매칭률이 임계 이하 | 앱 목록 조회 실패 의심 | 재조회 후 재시도 |
| 페이지 수 ≠ 인디케이터 표시 수 | 순회 누락 또는 과다 | `partial`로 표시 |
| 같은 번들 ID가 여러 슬롯에 | 중복 배치이거나 오식별 | 모델이 중복을 허용하는지에 따라 판단 |

**슬롯 충돌은 경보가 아니라 실패다.** 이것을 경고로 처리하고 진행하면 잘못된 좌표로 제스처를 재생하게 되고, 그 결과는 되돌릴 수 없다.

## 4. 멱등성과 안정화

추출은 여러 번 실행된다 — 최초 로드, 적용 중 검증, 적용 후 확인.

- **같은 상태에서 두 번 추출하면 같은 결과가 나와야 한다.** 그렇지 않으면 적용 중 검증이 오탐을 낸다
- 순회 중 애니메이션이 끝나기 전에 읽으면 결과가 흔들린다. 안정화 대기를 넣거나, 연속 2회 동일 결과를 확인한다
- 신뢰도 산출도 결정적이어야 한다. 같은 입력에 다른 신뢰도가 나오면 UI 표시가 깜빡인다

### 적용 중 검증용 경량 추출

전체 추출은 비싸다. 적용 루프에서 매 단계마다 전체를 다시 읽으면 시간이 배가된다.

**영향받은 페이지만 다시 읽는 경량 경로**를 제공하라. 이동 하나는 보통 한두 페이지에만 영향을 준다. 다만 조밀 채움 모드에서는 밀어내기가 여러 페이지로 전파될 수 있으므로, 경량 경로의 범위를 프로파일의 `allowsGaps`에 따라 다르게 잡는다.

## 5. 추출 결과 형식

```
ObservedLayout
  schemaVersion   : 스키마 버전
  extractedAt     : 추출 시각
  deviceProfile   : 사용한 프로파일 (source·verification 포함)
  completeness    : "complete" | "partial"
  pages[]         : 페이지별 슬롯 배치
  dock            : 독 배치
  unplaced[]      : 홈화면에 없는 설치 앱
  diagnostics
    slotConflicts     : 감지된 충돌 목록
    unresolvedCount   : Unknown 항목 수
    matchRate         : 번들 ID 매칭률
    warnings[]        : 교차 검증 경보
```

`diagnostics`를 선택 사항으로 두지 마라. UI가 "3개 항목을 인식하지 못했습니다"를 사용자에게 보여주려면 이 값이 필요하고, QA가 추출 품질을 추적하려면 이 값이 필요하다.
