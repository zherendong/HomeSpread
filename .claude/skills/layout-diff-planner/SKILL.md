# 布局差异规划：历史手势回退研究

2026-08-19，上游确认可通过 `com.apple.springboardservices` 的 `setIconState` 写入整份 plist。当前主路径因此不需要逐图标手势、顺延模拟器或断点续作。

**本文保留完整的历史设计方法，只适用于明确启动的替代路径研究。** 原样写回校验失败不会自动执行手势，也不会授权安装 WDA、切换开发者模式或更改设备。应先说明限制并确定替代任务范围。

## 问题性质

如果目标设备不能使用 `setIconState`，手势重放是候选替代方式之一；是否可用仍需验证，不能断言它必然可行。其他可能方向包括人工引导和特定受管理设备方案。

| 性质 | 影响 | 历史设计应对 |
|------|------|--------------|
| 慢 | 移动次数决定等待时间 | 降低计划成本 |
| 不稳定 | 错误放置可能没有协议报错 | 每步验证 |
| 无事务回滚保证 | 中断后可能处于部分完成状态 | 检查点、明确中断语义和恢复策略 |

## 工作顺序

1. 用实测建立成本函数。
2. 确认顺延规则。
3. 计算模型差异。
4. 安排满足前置条件的操作顺序。
5. 向用户展示预演结果。
6. 执行并逐步验证。
7. 报告完成、中断与未完成部分。

这些是研究方案的实施步骤，不能跳过授权在用户手机上试验。

## 1. 成本函数

不同操作的耗时不同。

| 操作 | 成本来源 |
|------|----------|
| 同页移动 | 基础拖动 |
| 移到相邻页 | 拖动加翻页等待 |
| 移到远处页面 | 拖动加多次翻页等待 |
| 放入文件夹 | 拖动加文件夹动画 |
| 移出文件夹 | 打开、拖出、关闭 |
| 解散文件夹 | 内部项目数乘以移出成本 |
| 创建文件夹 | 重叠拖放、创建动画、可能的命名 |
| 页面重排 | 是否需要进入另一编辑界面 |

由协议研究角色在获准的测试环境测量。不以任意常数冒充测量值。未测量时，将时间显示为未知或明确的研究估计，不能向用户承诺精确耗时。

同时考虑失败概率与重试成本。远距离跨页拖放可能更容易失败，但概率同样需要证据。

## 2. 顺延模型

历史模型用 `allowsGaps` 区分空位能力。该标记不是当前实现已提供的通用协议能力，规则必须在目标版本验证。

不允许空位时，可将部分布局视作有序列表：向前插入一个图标，中间项目顺延；页面满时，末项可能跨页传播。

直接按目标位置逐个移动可能失败：

1. 将 A 放到目标位置。
2. B、C、D 因顺延改变位置。
3. 再将 B 放到目标位置。
4. 第二次顺延又改变 A。
5. 先前工作失效。

因此每一步后必须根据规则模拟后续状态。缺少模拟会导致实际状态不断偏离计划，引发反复重新规划。

允许空位的模式减少了压紧规则的影响，但不能断言绝无顺延；创建、填补和保留空位本身仍有语义，需实测。

详细研究步骤见 `references/reflow-and-gestures.md`。

## 3. 计算差异

比较 `observed` 与 `desired`，生成模型操作。

### 原则

- 使用可靠标识对应项目；当前数据以 `displayIdentifier` 优先，不能把显示名称或位置当成身份，也不能强求所有应用都有 bundle ID。
- 低置信度与 `Unknown` 不自动进入计划。人工确认身份不等于确认未知结构的移动规则；不支持的结构仍保持不动。
- 若 `observed.completeness == partial`，不建立自动操作计划。缺失区域可能被顺延影响。
- 安装与删除应用不在布局整理范围。目标中不存在于设备的应用应报告警告，不生成安装操作。

### 历史操作类型

```text
Move         ：移到另一位置或页面
MoveToDock   ：移到程序坞，使用独立容量
IntoFolder   ：放入文件夹
OutOfFolder  ：移出文件夹
CreateFolder ：重叠两个图标创建文件夹
RenameFolder ：修改文件夹名称
ReorderPage  ：调整页面顺序
```

每种操作都应有前置条件。例如目标页面已满时，需先确定插入顺延是否可接受，或安排腾出位置。忽略前提就无法得到可执行顺序。

## 4. 制定计划

### 目标

寻找低成本、可验证的顺序。组合空间可能很大，可选择快速找到足够好的方案，而不承诺全局最优。

### 候选方法

| 方法 | 用途 |
|------|------|
| 临时位置 | 用空位打破循环依赖 |
| 按页拆分 | 先处理同页可完成的操作，减少翻页 |
| 逆序安排 | 在已验证的顺延规则下，可能降低传播 |
| 集中访问页面 | 合并同一页的操作，分摊切换成本 |

A、B 互换位置形成循环时，可能需要临时位置。若没有空位，应评估受支持的新页面操作，或报告无可行计划；不能随意清空其他项目。

### 计划结果

```text
Plan
  steps[]
    index          ：序号
    operation      ：操作
    from / to      ：位置
    expectedState  ：此步后的预期布局，作为验证依据
    estimatedMs    ：预计毫秒数及其证据来源
    riskLevel      ：失败风险
  totalSteps       ：总步骤数
  estimatedTotal   ：总预计时间
  warnings[]       ：应用缺失、排除的低置信度项目等
  infeasible[]     ：无法执行的操作及原因
```

`expectedState` 不可缺省，执行后需要明确的比较对象。

## 5. 预演

执行前必须展示：

- 总操作次数。
- 有依据的预计时间范围，例如“约 4～7 分钟”；该数字是表达示例，不是项目实测。
- 排除项目及原因。
- 不可行操作及原因。
- 会解散文件夹或改变大量布局的操作清单。

历史设计提出允许用户选择仅处理某些页面。部分计划必须重新验证依赖关系，不能把整体计划任意截断。该功能未在当前应用中实现。

不能有绕过预演和明确确认直接执行的路径。

## 6. 执行与验证循环

```text
对每个步骤：
  1. 转换为手势序列
  2. 执行
  3. 等待界面稳定
  4. 读取实际状态
  5. 与 expectedState 比较
     ├─ 一致：保存检查点，进入下一步
     └─ 不一致：停止原计划，依据当前实际状态重新规划
```

### 为什么不能跳过验证

若执行 20 步后才发现第 3 步已经偏离，后面 17 步可能无效甚至扩大损坏。验证会增加时间，但应以实际失败与返工成本决定频率；默认每步验证，不能用“更快”为由直接取消。

### 发现偏差时

把当前真实状态作为新的 `observed`，从差异计算重新开始。不能假设旧预期仍然成立，也不能自动执行用户未审阅的重大新计划。

## 7. 安全约定

这是未来若实施该方案必须满足的约束：

- **连续失败上限**：例如 3 次后停止；具体阈值需设计和测试，不无限重试。
- **用户取消**：在当前手势完成并退出编辑模式后停止，不能将手指悬停在拖动中间。
- **检查点**：记录每步完成状态；恢复时重新观察设备，不能仅按旧索引继续。
- **部分完成报告**：如“30 项中完成 22 项，剩余 8 项如下”，明确当前状态。数字仅为示例。
- **重大布局变化单独确认**：重置或解散文件夹时列出受影响内容，不能扩大原授权范围。
- **未知内容保护**：不自动移动未知或低置信度项目，也不以确认代替格式支持。
- **原始状态记录**：留存恢复依据，并说明该路径没有事务回滚保证。若整体写入路径不可用，不能承诺该备份一定可自动恢复。

当前 `setIconState` 主路径不采用此逐步重试和取消循环，其安全要求见 `homescreen-layout-model`。

## 8. 人工引导研究

相同计划可由人执行：应用提示待移动项目及目标，用户完成后确认下一步。

研究动机：

- 自动手势可能随 Apple 界面变化失效。
- 某些用户不能接受开发者模式、签名等准备。
- 少量操作时，人工可能更快。

执行者和验证方式不同：可以用自动读取验证，也可以由用户确认。虽然计划模型可能复用，交互与验证仍需实现和测试，不能据此推定成本很低或功能已存在。

如读取路径仍可用，人工移动后应重新检查实际结果并提示偏差。
