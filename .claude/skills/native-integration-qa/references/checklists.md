## 1. 기기 안전성 확장

- [ ] 적용 중 USB 연결이 끊기면 체크포인트가 남는가
- [ ] 재개 시 `lastVerified`와 현재 상태를 대조하고, 다르면 재계획하는가
- [ ] 앱이 실수로 실행되었을 때 복구 경로(홈 복귀 → 재진입 → 재추출)가 있는가
- [ ] 편집 모드 진입을 확인한 뒤 드래그를 보내는가 (확인 없이 보내면 앱이 실행된다)
- [ ] 편집 모드 종료가 성공/실패/취소 **모든 경로**에서 실행되는가
- [ ] 화면 잠김·전화 수신 등 방해 상황에서 중단하는가
- [ ] 프로파일이 `추정됨`일 때 사용자 확인을 요구하는가
- [ ] 슬롯 충돌 감지 시 추출을 실패로 처리하는가 (경고로 넘기지 않는가)
- [ ] 위젯 이동이 저신뢰일 때 계획에서 제외되는가
- [ ] 재시도 전에 현재 상태를 다시 읽는가 (부분 성공한 제스처를 반복하면 악화된다)

## 2. 경계면별 대조 항목

### 추출 파이프라인 ↔ 레이아웃 모델

- [ ] `ExtractionResult`의 필드가 모델이 기대하는 것과 일치하는가
- [ ] `completeness` 값 집합이 양쪽에서 같은가
- [ ] `diagnostics`가 실제로 채워지고, 소비자가 읽는가
- [ ] 신뢰도 값의 종류와 의미가 같은가

### 레이아웃 모델 ↔ UI

- [ ] `Unknown` 항목이 UI까지 도달하는가
- [ ] `unplaced`(미배치 앱)를 UI가 사용하는가
- [ ] UI가 제약 검사를 모델에 위임하는가, 자체 구현하는가 (자체 구현이면 결함)
- [ ] `observed`와 `desired`가 UI에서 분리 관리되는가

### 레이아웃 모델 ↔ 동기화 엔진

- [ ] 시뮬레이터가 `allowsGaps`를 읽는가
- [ ] 프로파일의 모든 용량 값(페이지, 독, 폴더)이 계획에 반영되는가
- [ ] 저신뢰·`Unknown` 항목 제외가 엔진에서 실제로 일어나는가

### 동기화 엔진 ↔ 기기 브리지

- [ ] 좌표 단위가 일치하는가
- [ ] 타임아웃 값의 단위가 일치하는가
- [ ] 제스처 실패의 표현이 일치하는가
- [ ] 취소 신호가 브리지까지 전달되는가

### 동기화 엔진 ↔ UI

- [ ] 엔진이 발행하는 이벤트와 UI가 구독하는 이벤트 목록이 일치하는가
- [ ] 부분 성공 결과를 UI가 "실패"로 표시하지 않는가
- [ ] 드라이런 결과 형식이 UI가 표시하려는 항목을 모두 포함하는가

## 3. 좌표계 감사

좌표를 다루는 **모든** 지점을 찾아 나열하고, 각각에 대해:

- [ ] 어느 좌표계의 값인가가 이름이나 타입으로 드러나는가
- [ ] 변환이 지정된 한 곳에서만 일어나는가
- [ ] 원점과 방향이 계약과 일치하는가
- [ ] DPI 배율 적용 여부가 명확한가
- [ ] 슬롯 중심 계산이 아이콘 이미지 영역 기준인가 (라벨 포함 영역이면 행 판정이 밀린다)

`grep`으로 좌표 관련 식별자를 전수 검색해 목록을 만든 뒤 하나씩 확인하라. 눈으로 훑어서는 놓친다.

## 4. 오류 처리 경로

각 실패 상황이 **사용자에게 도달할 수 있는 메시지**로 이어지는지 끝까지 추적한다.

| 상황 | 사용자 메시지가 있는가 | 다음 행동을 안내하는가 |
|------|--------------------|-------------------|
| 기기 미연결 | | |
| 신뢰하지 않음 | | |
| 개발자 모드 꺼짐 | | |
| 서명 만료 | | |
| 외부 도구 없음 | | |
| 외부 도구 버전 불일치 | | |
| 추출 부분 실패 | | |
| 프로파일 추정됨 | | |
| 적용 중 연결 끊김 | | |
| 연속 실패로 중단 | | |

- [ ] 어떤 경로에서도 원시 예외 메시지가 사용자에게 그대로 노출되지 않는가
- [ ] 내부 용어(WDA, usbmuxd, lockdownd, 접근성 트리)가 UI 문자열에 없는가
- [ ] 로그에는 원시 정보가 남는가 (사용자 메시지는 순화하되 진단은 보존)

## 5. 사용자 경험

- [ ] 첫 화면이 캔버스인가 (설정·설명 화면이 앞을 막고 있지 않은가)
- [ ] 미적용 변경 수가 항상 보이는가
- [ ] 미적용 변경이 있는 채로 앱을 닫으려 하면 경고하는가
- [ ] 드롭 전에 유효한 목적지가 표시되는가
- [ ] 밀어내기가 드롭 전에 미리보기되는가
- [ ] 실행 취소가 드래그 단위로 동작하는가
- [ ] 적용 진행 중 취소 버튼이 항상 활성인가
- [ ] 부분 성공 시 완료된 것과 남은 것이 모두 나열되는가
- [ ] 긴 작업(추출, 적용)에 진행 표시가 있는가

## 6. Windows 환경

- [ ] 125% / 150% / 175% 배율에서 좌표가 정확한가
- [ ] 다중 모니터 간 창 이동 시 배율 변경을 처리하는가
- [ ] 창 크기 변경에 캔버스가 대응하는가
- [ ] 적용 루프(수 분) 동안 UI가 응답하는가
- [ ] 관리자 권한이 필요하면 그 사실을 사전에 안내하는가
- [ ] 번들된 외부 실행 파일의 경로가 설치 위치에 무관하게 해결되는가
- [ ] 경로에 공백·한글이 포함된 설치 위치에서 동작하는가

## 7. 수용 기준 추적

`_workspace/01_product-strategist_requirements.md`의 각 `REQ-###`에 대해:

| 상태 | 의미 |
|------|------|
| 충족 | 실행하거나 코드를 대조해 확인함 |
| 미충족 | 확인했고 만족되지 않음 |
| 부분 | 일부 조건만 만족 |
| 미검증 | 확인할 수 없었음 + 사유 필수 |

- [ ] 모든 MVP 요구가 표에 있는가 (누락된 요구가 있으면 그것부터 보고)
- [ ] `미충족`과 `미검증`을 구분했는가
- [ ] `미검증`마다 사유가 있는가
