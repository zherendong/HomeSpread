# 接口契约：模块边界的约定

## 为什么需要契约

界面、同步层、布局模型和设备桥接可以由不同成员并行实现。如果各自猜测对方的格式，差异会直到集成时才暴露。

这里的差异可能表现为主屏幕布局错误，而非编译报错。例如两方分别假设位置原点在左上角和左下角，就可能无错误地移动到错误位置。

**契约是设备数据安全的一部分。**

## 契约文件

路径：`_workspace/02_contracts/{name}.contract.md`。

| 文件 | 负责人 | 消费方 |
|------|--------|--------|
| `layout-model.contract.md` | homescreen-model-analyst | 界面、同步层、设备桥接 |
| `device-bridge.contract.md` | ios-protocol-specialist | 同步层、读取或提取层 |
| `sync-engine.contract.md` | layout-sync-engineer | 界面 |
| `ui-viewmodel.contract.md` | ui-engineer | 同步层，尤其是进度事件 |

同一契约只能有一个负责人。其他成员提出修改，由负责人协调落实。

## 必须明确的事项

| 事项 | 原因 |
|------|------|
| 位置索引原点与方向 | 明确左上角、按行优先，避免各模块自行解释 |
| 坐标单位 | 区分逻辑像素、物理像素及是否已应用 DPI 缩放 |
| 页面索引起点 | 明确从 0 还是 1 开始 |
| 程序坞表达 | 是页面数组元素，还是独立字段；当前原始 plist 的第 0 项是程序坞 |
| 部分失败 | 明确结果可否用于展示或写入；不完整结果不能当成完整布局应用 |
| 时间单位 | 明确毫秒或秒 |
| 异步事件顺序 | 是否保证顺序、是否可能丢失 |
| 取消含义 | 立即取消、检查点取消或操作期间禁止关闭；整体写入不能假装可即时撤销 |
| 字段缺失与 null | 区分“不存在”“没有值”和“未知” |
| 设备归属 | 明确设备键、备份归属和拒绝跨设备恢复的行为 |
| 写入前置条件 | 说明原样写回校验、旧状态检查、备份及确认要求 |

## Unknown 与历史置信度模型

当前 `Unknown` 的内容与位置必须保留，消费者不能将它当作空位或可自由移动的普通图标。

历史截图识别方案提出 `confidence` 字段：界面区分低置信度，手势计划排除不可靠项目。这是需要显式约定的条件性扩展，当前 plist 模型没有这一通用字段。若启用该方案，必须把字段与阈值写入契约，不能让消费者猜测。

## 修改流程

1. 发现变更需要时，先通知契约负责人；消费方不能只修改自己一侧。
2. 负责人更新契约并调整版本。
3. 通知全部消费方，在变更记录中写明影响。
4. 消费方确认是否需要修改并回应。
5. 未收齐回应前，不将新契约下的实现视为集成完成。

### 版本规则

| 修改 | 版本级别 | 消费方动作 |
|------|----------|------------|
| 新增可选字段 | minor | 可忽略时无需修改 |
| 新增必填字段 | major | 必须处理 |
| 删除字段或修改语义 | major | 必须处理 |
| 新增枚举值 | major | 必须处理未知分支 |

不能把新增枚举值一概当成 minor；穷举分支的消费者可能因此出现未处理路径。

## 契约校验

同时对照契约、生产方实现和消费方实现。

| 检查项 | 常见缺陷 |
|--------|----------|
| 字段名 | 一方用 `slotIndex`，另一方用 `slot` |
| 类型 | 一方是字符串，另一方是数字 |
| 必填性 | 生产方不发送，消费方却必读 |
| 枚举 | 生产方发出消费方未处理的值 |
| 单位 | 一方为毫秒，另一方为秒 |
| 部分失败 | 生产方返回 `partial`，消费方忽略后继续写入 |
| 事件 | 界面等待从不发出的事件 |
| 安全前置条件 | 某条写入路径绕过备份、设备匹配或用户确认 |

“存在契约文件”不等于已验证。必须检查文档与两端代码是否一致。

## 编写顺序

设计共享边界时，先确定契约再依赖它实现：

1. 布局模型契约，作为共同基础。
2. 设备桥接契约，根据实际协议研究与代码确定。
3. 同步层契约，依赖前两者。
4. 界面视图模型契约，依赖前三者。

布局模型改变会影响其余三个边界，应投入充分的交叉审查。
