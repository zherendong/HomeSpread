协议实现成本较高，优先评估已有工具。当前 HomeSpread 使用 `pymobiledevice3`；本文件提供重新评估时的方法，不声称所有候选工具当前都满足需求。

## 1. 工具类别

工具能力会变化，应核对实际采用的版本。下面按类别介绍候选工具，不保证其最新版本满足需求。

### 1.1 连接和设备服务

库或 CLI 实现 USB 多路复用、配对认证和服务启动；不同工具可能提供设备发现、应用列表、安装、截图或开发者镜像等不同能力。

检查：

- 是否提供目标平台构建，或需要本地编译。
- 是否兼容所需 iOS 认证、服务和隧道机制；当前布局服务不需要开发者隧道。
- 可否直接作为库调用，还是只能启动 CLI。
- macOS 是否支持本机架构，Windows 是否依赖已安装的 Apple 服务。

### 1.2 UI 测试自动化

WDA 等工具基于 Apple 测试框架，向客户端暴露元素树和手势接口。

这是 HomeSpread 历史回退研究，当前布局读写不依赖它。若明确评估该路径，检查：

- 设备端组件由谁签名，如何安装。
- 签名有效期与重装条件。
- Windows 能否使用已有构建，是否仍需 macOS 构建环境。
- SpringBoard 暴露的结构与普通应用是否不同。

### 1.3 其他语言的协议实现

例如同类协议可在不同语言生态中实现。与技术栈一并评估；同语言库可能减少 IPC，但不能仅凭语言一致就忽略稳定性和许可。

### 1.4 仅获取画面的路径

USB 视频采集、无线镜像接收等只提供像素。当前布局管理不需要实时视频，也不要求截图才能获得主屏幕结构。

只有任务明确需要实时预览时才研究这些路径。涉及内容保护绕过的方案需单独评估，不因能获得画面就直接采用。

## 2. 实际检查事项

不要只读 README 首页。

| 项目 | 来源 | 检查内容 |
|------|------|----------|
| 目标 iOS 支持 | 文档、源码、问题记录 | 对应版本、已知错误和未解决问题 |
| 维护状态 | 提交与发布历史 | 最近活动、修复速度；不能只按更新时间判定质量 |
| macOS / Windows 实际可用性 | 构建产物、测试、问题记录 | 架构支持、真实运行报告、平台特定限制 |
| 前置条件 | README、安装说明、问题记录 | 权限、驱动、额外软件 |
| 许可证 | 实际 LICENSE 文件 | 不只看项目简介 |
| 传递依赖许可 | 依赖清单与安装结果 | 主项目宽松不代表依赖也宽松 |

每项结论记录检查日期、依赖版本与环境。“去年能用”只构成历史证据，不能证明当前设备可用。

## 3. 许可证与分发

先确定分发形式，再核对具体许可证和依赖关系。免费与开源不免除义务。

| 分发形式 | 重点 |
|----------|------|
| 免费、开源 | 许可证兼容性、版权告知、完整对应源码及适用构建材料 |
| 免费、闭源 | copyleft 要求与许可兼容性；不能仅以免费规避要求 |
| 商业分发 | 上述要求，以及适用的专利、商标和组件条款 |

独立进程、静态或动态链接可能影响分析，但“用子进程调用就没有源码义务”不是可靠规则。应依据具体组件、许可证和组合方式判断；不确定时明确报告，不编造法律结论。

当前项目使用 GPL-3.0-or-later，分发修改版时需随附相应告知和对应源码获取方式。保留法律许可证原文，不用自行翻译替代正式文本。

## 4. 选型记录模板

```markdown
### 工具：<名称>
- **作用**：<在本项目中承担什么>
- **平台支持**：[已确认|资料依据|未验证] <macOS / Windows、架构与证据>
- **目标 iOS 支持**：[已确认|资料依据|未验证] <版本、证据、日期>
- **许可证**：<SPDX 标识>；实际分发义务：<内容>
- **再分发**：允许 | 不允许 | 尚待核对
- **前提**：<权限、驱动、外部软件>
- **调用方式**：库 | 可执行程序
- **选择**：采纳 | 待评估 | 不采用；理由：<内容>
- **替代候选**：<有证据的候选，或明确尚未调查>
```

记录替代方向可以降低未来故障的调查成本，但不能为了填满字段虚构一个可用备选。替换工具是条件性后续任务，由当前路径出现兼容性或许可问题触发。
