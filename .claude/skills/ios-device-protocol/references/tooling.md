## 1. 도구군 분류

각 도구의 최신 상태는 반드시 직접 확인한다. 아래는 **어떤 종류의 도구가 존재하는지에 대한 지도**이지, 각 도구의 현재 능력에 대한 보증이 아니다.

### 1-1. 연결·기기 서비스 계층

Apple의 기기 통신 프로토콜(USB 다중화, 인증, 서비스 시작)을 구현한 라이브러리·CLI 계열. 기기 열거, 페어링, 앱 설치·목록 조회, 스크린샷, 개발자 이미지 마운트 등을 제공한다.

이 계층에서 확인할 것:
- Windows 빌드가 공식 제공되는가, 직접 빌드해야 하는가
- 최신 iOS의 인증·터널 방식 변화에 대응했는가
- 라이브러리로 링크 가능한가, CLI 실행 파일 호출만 가능한가

### 1-2. 자동화 계층 (UI 테스트 프레임워크 기반)

Apple의 UI 테스트 프레임워크 위에서 동작하며, 화면 요소 트리 조회와 제스처 주입을 HTTP 등으로 노출하는 서버 계열. 이 제품에서 **홈화면 구조 읽기와 아이콘 이동 모두**를 담당할 가능성이 높다.

이 계층에서 확인할 것:
- 기기에 설치할 앱의 **서명을 누가 어떻게 하는가**. 이것이 최대 마찰 지점이다
- 서명 유효기간과 재설치 주기. 사용자가 주기적으로 겪을 마찰이다
- Windows에서 빌드 없이 배포·구동이 가능한가, 아니면 macOS 빌드 머신이 필요한가
- 홈화면(런처)의 요소 트리를 읽을 수 있는가. 일반 앱과 시스템 런처는 접근성 노출이 다를 수 있다

### 1-3. 프로토콜 구현 (다른 언어 생태계)

같은 프로토콜을 다른 언어로 구현한 프로젝트들이 있다. 스택 선정과 맞물려 검토한다 — 앱의 주 언어와 같은 생태계의 구현이 있으면 통합 비용이 크게 준다.

### 1-4. 화면 캡처 전용 경로

USB 비디오 캡처, 무선 미러링 수신 등 화면 픽셀만 얻는 경로. **이 제품에서는 우선순위가 낮다.** 홈화면 편집에는 실시간 비디오가 필요 없고, 정지 스크린샷으로 충분하기 때문이다.

실시간 미리보기를 부가 기능으로 넣기로 결정한 경우에만 조사한다. 그 경우에도 콘텐츠 보호 우회 가능성이 있는 경로는 법적 검토 전에 도입하지 않는다.

## 2. 조사 시 실제로 확인할 것

문서의 첫 페이지만 읽고 판단하지 마라. 다음을 직접 확인한다:

| 확인 대상 | 어디서 | 무엇을 보나 |
|----------|--------|-----------|
| 최신 iOS 대응 | 이슈트래커 | 최근 iOS 버전 번호로 검색. 미해결 이슈가 쌓여 있는지 |
| 실제 유지 상태 | 커밋 이력·릴리스 | 마지막 릴리스 시점. 이 분야에서 1년 넘게 방치된 도구는 위험 |
| Windows 실사용 | 이슈트래커 | "Windows" 키워드 이슈. 문서에 지원한다고 적혀 있어도 실사용 보고가 없으면 의심 |
| 사전 요구사항 | README + 이슈 | 관리자 권한, 드라이버, 별도 설치 요구 |
| 라이선스 | LICENSE 파일 | README의 서술이 아니라 실제 파일 |
| 의존성의 라이선스 | 의존성 목록 | 본체가 허용적이어도 의존성이 제약적일 수 있다 |

**중요:** 이 도구들의 능력은 iOS 업데이트로 바뀐다. "작년에는 됐다"는 정보는 근거가 되지 못한다. 조사 결과에 확인 일자를 반드시 병기하라.

## 3. 라이선스 판단

배포 형태에 따라 의무가 달라지므로, **배포 형태를 먼저 정하고** 판단한다.

| 배포 형태 | 라이선스 검토 초점 |
|----------|------------------|
| 무료·오픈소스 배포 | 대부분 문제 없음. 고지 의무만 확인 |
| 무료·클로즈드 배포 | 카피레프트 계열의 소스 공개 의무 여부. 정적/동적 링크 구분이 중요 |
| 상용 배포 | 위 + 특허 조항, 상표 조항 |

판단이 애매한 경우:
- **별도 프로세스로 실행 파일을 호출**하는 형태가 링크보다 의무가 가벼운 경우가 많다. 이것이 아키텍처 결정(외부 도구를 프로세스로 분리)의 근거가 될 수 있다
- 확신이 서지 않으면 **결론을 내리지 말고 리스크로 보고하라.** 라이선스 오판은 배포 후 되돌리기가 가장 비싼 실수다

## 4. 선정 결과 기록 형식

```markdown
### 도구: <이름>
- **역할**: <이 프로젝트에서 담당할 것>
- **Windows 지원**: [확인됨|문헌|미검증] <근거>
- **최신 iOS 대응**: [확인됨|문헌|미검증] <근거 + 확인 일자>
- **라이선스**: <SPDX 식별자> / 배포 형태별 의무: <...>
- **재배포**: 가능 | 불가 (사용자 설치 안내 필요)
- **사전 요구**: <관리자 권한 / 드라이버 / 별도 설치>
- **호출 형태**: 라이브러리 | 실행 파일
- **선정 여부**: 채택 | 보류 | 탈락 — 사유: <...>
- **대체 후보**: <이 도구가 깨졌을 때의 대안>
```

`대체 후보`를 비워두지 마라. 이 분야의 도구는 iOS 업데이트로 깨지며, 그때 대안을 처음부터 조사하면 제품이 몇 주 멈춘다.
