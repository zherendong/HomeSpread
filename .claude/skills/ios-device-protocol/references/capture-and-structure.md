# 主屏幕读取：布局、截图与应用识别

说明当前布局读取，以及历史研究中的截图、无障碍树和应用目录组合。

**当前 HomeSpread 直接使用 `getIconState` 获取布局，通过独立接口获取图标与安装列表。** 不需要翻页截图，不需要 WDA。下面第 2、3、5、6 节保留的是条件性回退提取设计，不是已启用功能。

## 1. 各类数据的作用

| 数据 | 能提供什么 | 不能替代什么 |
|------|------------|--------------|
| 原始 iconState | 页面、程序坞、文件夹和项目标识及原始字段 | 不能保证包含所有未来 iOS 特性的可编辑语义 |
| 无障碍树 | 可见元素位置、标签和部分层级 | 标签不能保证可靠身份，通常不提供完整图标图片 |
| 截图 | 外观像素 | 不能直接提供文件夹内部、完整结构与可靠身份 |
| 已安装应用列表 | bundle ID、名称及部分元数据 | 不直接给出主屏幕位置 |
| SpringBoard 图标服务 | 部分项目的 PNG 图标 | 网页快捷方式等可能没有可获取的图标 |

早期方案提出以 bundle ID 联合树、截图和安装目录。当前原始布局已经提供结构与标识，安装列表用于补充信息和潜在回填提示，不能要求所有读取都必须组合三种图像相关来源。

## 2. 历史结构读取：无障碍树

### 原理

UI 测试框架可能以层级树暴露界面元素，包含 `label` 与 `rect`。结构化数据通常比单纯从像素反推网格更便于解析，但 SpringBoard 的可访问范围必须实测，不能由普通应用的支持推断。

### 设计前检查

- 系统启动器是否实际暴露所需元素。这是首要可行性检查。
- 元素类型名称是否随 iOS 变化，避免依赖未经验证的固定字符串。
- 文件夹关闭和打开时分别如何表达，读取内部是否必须打开；打开属于界面状态变化。
- 程序坞是否有独立容器，还是只能按坐标判断。
- 小组件是否具有足够的标签和结构；缺失时如何保留未知信息。
- 搜索、App 资源库是否是独立界面。
- 不在屏幕内的其他页面是否也出现在树中；若有，不一定需要逐页遍历。

### 解析原则

- 用图标图像区域的中心映射网格，不把文本标签一起计算，否则行判断可能偏移。
- 不假设树顺序与视觉顺序相同；根据已验证坐标规则排序。
- 未知元素保留为 `unresolved` 或 `Unknown`。不能丢弃后把位置显示为空白。

## 3. 历史外观读取：截图

### 用途

1. 提供页面外观预览。
2. 与结构读取交叉核对图标数量和位置。
3. 在结构路径不可用时研究图像识别，但低质量识别不能直接用于自动写入。

当前画布按布局和图标绘制，并不以真实整屏截图作为页面底图。

### 获取路径

不同服务或自动化工具可提供截图，前提随工具和 iOS 变化。选用已验证且任务必需的最小路径；不能为了截图擅自引入 WDA 或开发者环境。

### 图像身份识别的候选方法

1. **图标图像匹配**：将候选区域与已获取图标比较。
2. **标签 OCR**：读取图标下的名称，注意本地化、截断和对比度。
3. **仅定位**：知道有项目，但不知道身份，必须标记未知。

不能仅凭方法名称保证固定准确率。深色、着色或自定义主题可能影响匹配；匹配失败必须表示“未知”，不能表示“空位”。

## 4. 应用身份与安装列表

### 为什么不能用显示名称作键

- 同一应用可能因语言不同而名称不同。
- 不同应用可以同名。
- 更新可能改变名称。

早期文档称“bundle ID 只能从安装列表获取”，该说法不准确。当前 iconState 可含 `displayIdentifier` 或 `bundleIdentifier`，优先保留这些来源。已卸载但保留图标的应用可能只有 `displayIdentifier`。

### 历史识别组合过程

1. 建立 `{bundle ID → 名称、可获取图标}` 目录。
2. 用树标签寻找候选。
3. 唯一名称匹配可增加置信度，但不能脱离其他证据就绝对确认身份。
4. 多候选时比较图标。
5. 无匹配时考虑系统应用、文件夹、小组件、别名或目录缺失，保留 `unresolved`，不编造身份。

系统应用可能需要单独查询。当前实现查询用户应用和系统应用，并筛选可能显示在主屏幕上的系统项；不能仅查用户应用就保证回填提示完整。

## 5. 历史页面遍历

仅在明确启用截图或无障碍研究路径时使用。遍历会改变设备界面状态，必须纳入任务授权。

### 步骤

1. 确认当前页面，按已验证方式到达起始主屏幕。
2. 根据页面指示器或已验证结束条件判断总页数。
3. 每页保存结构与截图。
4. 滑动到下一页，等待动画稳定后读取。
5. 通过内容不再变化、到达 App 资源库等信号判断结束，避免无限滑动。

### 常见问题

- **动画中读取**：两页混合或坐标漂移。等待稳定，必要时比较连续结果。
- **页数误判**：隐藏页、App 资源库、今天视图不能未经区分算作普通主屏幕。
- **意外触发应用或编辑模式**：滑动起点应避开可点击项目，并检测实际状态。
- **中途失败**：保留已读页面作为诊断结果，并明确失败位置及 `partial`；不完整数据不能用于整体写入。

## 6. 历史融合与置信度

若实施识别方案，置信度必须具有可测试的含义。

| 等级 | 证据示例 | 下层处理 |
|------|----------|----------|
| 高 | 坐标、可靠身份与交叉检查一致 | 满足其余约束后才可考虑编辑 |
| 中 | 坐标与身份候选存在，但缺少交叉检查 | 明确标记；是否自动执行需另定门槛 |
| 低 | 位置已知、身份未知 `unresolved` | 明确展示，不自动移动 |
| 无 | 区域未读到 | 表示“未读取区域”，不能表示空白 |

用户确认身份不等于未知布局结构已经受支持。当前产品保留原始未知内容，不采用这一通用置信度接口。

### 交叉核对

- 树中图标数与截图识别数。
- 页面数与指示器。
- 可靠标识匹配率，过低时检查应用目录和识别过程。
- 网格位置冲突，发现后停止自动规划并检查坐标或配置。

**未读到和空白必须严格区分。** 否则计划会把其他图标放到未知区域，影响原有内容。
