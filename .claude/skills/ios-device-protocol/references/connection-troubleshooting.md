# 连接问题诊断

先定位失败阶段，再选择处理方式。当前 HomeSpread 的必需路径到 SpringBoard 布局服务为止；WDA、开发者镜像与隧道只属于另行启用的历史自动化研究。

## 诊断顺序

逐层确认。上层基础条件不成立时，不要盲目检查更深的自动化组件，也不要让用户为当前路径安装不需要的工具。

## 第 1 层：USB 枚举

**检查**：操作系统是否识别到 USB 设备。macOS 可检查访达或系统信息，Windows 可检查设备管理器。

| 现象 | 常见原因 |
|------|----------|
| 完全看不到设备 | 仅充电线缆、接口故障、集线器问题 |
| 显示未知设备 | Windows 驱动缺失或识别异常 |
| 反复出现又消失 | 接触不良、供电或接口问题 |

充电正常不能证明数据线支持数据传输。必要时使用已知可靠的数据线直接连接电脑。

## 第 2 层：多路复用服务

**检查**：设备发现接口是否返回 USB 设备。日志只保留允许的脱敏标识。

| 现象 | 可能原因 |
|------|----------|
| 列表为空 | 未连接、服务不可用、USB 访问受限 |
| 无法访问服务 | macOS 系统服务或 Windows Apple 组件异常 |
| 间歇识别 | 连接不稳定，或重复实现相互干扰 |

macOS 使用系统 USB 多路复用 Unix socket；Windows Apple 组件通常使用本机 TCP 端口。不能用 Windows 的 `127.0.0.1:27015` 判断 Mac 是否就绪。

优先使用系统组件，避免无必要地启动第二套实现。如果多个 USB iPhone 同时连接，当前 GUI 拒绝含糊选择；CLI 可以明确指定 `--udid`。当前路径不自动退到 Wi‑Fi。

若命令在受限执行环境内失败，应先区分宿主隔离与真实服务故障，不能立即要求用户重新配对或更改设备权限。

## 第 3 层：配对与信任

**检查**：能否建立配对连接并读取必要设备信息。

| 现象 | 可能原因 | 用户指引 |
|------|----------|----------|
| 提示需要信任 | 尚未批准 | 检查 iPhone 屏幕，Mac 同时检查访达 |
| 不出现信任提示 | iPhone 锁定 | 先解锁并保持解锁 |
| 曾信任仍再次要求 | 配对记录丢失、设备重置或设置变化 | 按提示重新建立信任 |
| 点击信任仍失败 | 配对记录无法保存或访问 | 检查应用数据目录权限，不公开配对文件 |

设备锁定是常见原因，应先明确提示解锁，而不是让用户反复寻找不存在的对话框。当前应用把自身配对缓存保存在私有数据目录；它包含敏感配对材料，不应作为普通日志分享。

## 第 4 层：目标服务

**检查**：能否启动当前需要的 SpringBoard 或安装列表服务。

| 现象 | 可能原因 |
|------|----------|
| SpringBoard 服务被拒绝 | 锁定、连接状态、设备策略或版本兼容性 |
| 安装列表失败但布局已读到 | 补充查询失败，不能据此否定原始布局读取，也不能保证回填名单完整 |
| 只在某个 iOS 版本失败 | 服务行为变化，需要对应版本证据 |
| 仅在某权限环境成功 | 先检查宿主权限或隔离，不默认要求管理员运行 |

只有另行启用开发者服务时，才调查 DDI、开发者模式或隧道前提。不能将“某服务失败”统一解释为“没有挂载开发者镜像”。记录目标版本范围和各自前提，避免无证据地套用同一修复。

## 第 5 层：历史自动化路径

当前产品无需执行这一层。若明确研究 WDA，检查元素树或手势接口是否有响应。

| 现象 | 可能原因 |
|------|----------|
| 设备没有组件 | 未安装 |
| 已安装却无法启动 | 签名、权限或运行配置问题 |
| 已启动但电脑连不上 | 转发或通道配置错误 |
| 接口有响应，主屏幕树为空 | SpringBoard 暴露限制，可能属于路径可行性问题 |
| 一段时间后失效 | 签名有效期等周期性前提变化 |

若采用该方案，签名过期可能形成重复的用户成本，应明确检测和处理方式。主屏幕数据根本不可获得时，应报告可行性限制，不能继续盲目重装工具。

## 诊断记录模板

```markdown
### 失败诊断
- **阶段**：第 3 层，配对与信任
- **观察**：<准确错误，必要时脱敏>
- **环境**：<macOS / Windows 版本>、iOS <版本>、设备 <型号>、权限或隔离条件
- **复现性**：总是 | 间歇 | 仅一次
- **尝试与结果**：<具体内容>
- **结论**：<已定位原因，或明确尚未定位>
- **用户提示**：<下一步可执行的指引>
```

诊断不仅要说明原因，还要帮助用户知道下一步做什么。
