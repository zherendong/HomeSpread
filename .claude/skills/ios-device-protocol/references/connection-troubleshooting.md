# 연결 문제 진단

"연결 실패"는 진단이 아니다. 실패는 다섯 단계 중 한 곳에서 일어나며, 각 단계마다 원인과 해결이 전혀 다르다. 단계를 특정하지 않은 채 해결을 시도하면 무작위로 헤매게 된다.

## 진단 순서

아래로 내려가며 각 단계가 통과하는지 확인한다. **위 단계가 실패하면 아래는 볼 필요 없다.**

---

## 1단계: USB 열거

**확인**: 운영체제가 기기를 USB 장치로 인식하는가. 장치 관리자에서 확인한다.

| 증상 | 흔한 원인 |
|------|----------|
| 장치가 전혀 안 보임 | 충전 전용 케이블, 포트 불량, 허브 문제 |
| 알 수 없는 장치로 표시 | 드라이버 미설치 |
| 나타났다 사라짐 반복 | 케이블 접촉 불량, 전력 부족 |

**주의**: 충전은 되는데 데이터 통신이 안 되는 케이블이 흔하다. 사용자에게 "케이블을 바꿔 보라"고 안내하는 것이 실제로 유효한 조언이다.

---

## 2단계: 다중화 데몬 인식

**확인**: 기기 열거 명령이 기기 식별자(UDID)를 반환하는가.

| 증상 | 흔한 원인 |
|------|----------|
| 빈 목록 | 데몬 서비스 미실행 |
| 서비스 자체가 없음 | 필요한 구성요소 미설치 |
| 간헐적 인식 | 여러 구현이 동시에 같은 포트를 점유 (충돌) |

**충돌은 진단이 어렵다.** 시스템에 설치된 기존 도구와 앱이 번들한 구현이 동시에 돌면 서로를 방해할 수 있다. 이 가능성을 초기에 확인하고, 아키텍처 결정(자체 구현 번들 vs 시스템 구성요소 사용)에 반영하라.

---

## 3단계: 페어링과 신뢰

**확인**: 기기 정보 조회가 성공하는가.

| 증상 | 흔한 원인 | 사용자 안내 |
|------|----------|-----------|
| 신뢰 필요 오류 | 기기에서 "신뢰"를 누르지 않음 | 기기 화면 확인 요청 |
| 신뢰 대화상자가 안 뜸 | **기기가 잠겨 있음** | 기기 잠금 해제 먼저 |
| 이전에 신뢰했는데 다시 요구 | 페어링 레코드 소실, 기기 초기화, 설정 재설정 | 재페어링 |
| 신뢰를 눌러도 계속 실패 | 페어링 레코드 저장 경로 권한 문제 | 앱 권한 확인 |

**가장 흔한 함정**: 기기가 잠긴 상태에서는 신뢰 대화상자가 나타나지 않는다. 사용자는 "아무것도 안 떴다"고 보고한다. 앱은 이 상황을 감지해 "iPhone 잠금을 해제해 주세요"를 먼저 안내해야 한다.

---

## 4단계: 서비스 시작

**확인**: 필요한 서비스(스크린샷, 앱 목록, 테스트 실행 등)를 실제로 열 수 있는가.

| 증상 | 흔한 원인 |
|------|----------|
| 특정 서비스만 실패 | 개발자 이미지 미마운트 |
| 개발자 관련 서비스 전부 실패 | 기기의 개발자 모드가 꺼져 있음 |
| 최신 iOS에서만 실패 | 서비스 접근 방식이 바뀜 (터널 요구 등) |
| 관리자 권한으로만 성공 | 터널·드라이버가 상위 권한을 요구 |

이 단계의 실패는 **iOS 버전에 따라 원인이 다르다.** 대상 iOS 버전 범위를 정하고, 각 버전에서 요구되는 사전 조건을 표로 정리하라. 버전별 분기 없이 하나의 경로를 가정하면 일부 사용자에게서만 실패한다.

---

## 5단계: 자동화 계층

**확인**: 화면 요소 트리 조회나 제스처 주입이 응답하는가.

| 증상 | 흔한 원인 |
|------|----------|
| 자동화 앱이 기기에 없음 | 미설치 |
| 설치는 됐는데 실행 실패 | **서명 만료** |
| 실행됐는데 PC에서 접속 불가 | 포트 포워딩 미설정 |
| 응답은 하는데 홈화면 요소가 비어 있음 | 시스템 런처의 접근성 노출 제약 — **경로 자체의 타당성 문제** |
| 처음엔 되다가 일정 기간 후 실패 | 서명 유효기간 만료 (재발성 마찰) |

**서명 만료는 일회성 오류가 아니라 반복되는 사용자 마찰이다.** 제품 설계에서 이것을 어떻게 다룰지(자동 감지 + 재설치 안내)를 반드시 정하라. 오류 메시지로만 처리하면 사용자는 앱이 고장 났다고 판단한다.

마지막 항목(홈화면 요소가 비어 있음)은 다른 것들과 성격이 다르다. 이것은 설정 문제가 아니라 **접근 경로 자체가 성립하지 않는다는 신호**이며, 발견 즉시 제품 범위 재검토가 필요하다. 리더에게 즉시 보고하라.

---

## 진단 결과 기록

```markdown
### 실패 진단
- **실패 단계**: 3단계 (페어링/신뢰)
- **관측된 증상**: <정확한 오류 문자열>
- **환경**: Windows <버전> / iOS <버전> / 기기 <모델> / 관리자 권한 <여부>
- **재현성**: 항상 | 간헐적 | 1회
- **시도한 것과 결과**: <...>
- **결론**: <원인 특정 또는 미상>
- **사용자에게 보일 문구**: <행동 가능한 안내로 번역>
```

마지막 항목을 빠뜨리지 마라. 진단의 목적은 원인 파악이 아니라 **사용자가 다음에 무엇을 하면 되는지 알려주는 것**이다.
