# iOS 设备协议：连接未越狱的 iPhone

本技能说明通信层的组成、当前路径与调查方法。

## 如何使用本技能

这是一份调查地图，不是永远有效的结论表。Apple 的设备协议会变化，在线资料可能过时。采用结论前，应核对项目代码、依赖版本和实测证据。

当前 HomeSpread 使用 `pymobiledevice3` 访问 SpringBoard 布局服务，通过 USB 读取、备份和整体写入。macOS 已内置连接服务；Windows 需要 Apple Devices 或 iTunes。当前主路径不需要越狱、开发者模式、Xcode、开发者镜像或 WDA。

## 证据标记

协议结论必须区分：

| 标记 | 含义 | 条件 |
|------|------|------|
| `[已确认]` | 在明确环境中复现 | 留下命令、输出和日期；历史确认不能冒充当前设备确认 |
| `[资料依据]` | 来自工具文档、源码或问题记录 | 附来源 URL 或仓库路径 |
| `[未验证]` | 假设或尚未实测 | 不能据此宣称产品能力已经成立 |

过时假设会连带影响其他模块。标记证据等级，才能明确优先验证什么。

## 协议层次

```text
[macOS / Windows 桌面应用]
     │
     ├─ 连接层 ─── usbmuxd（USB 多路复用）→ lockdownd（配对、认证、启动服务）
     │                ↓
     ├─ 当前服务 ─ SpringBoard 布局与图标、安装应用列表
     │
     └─ 条件性回退研究
          ├─ 开发者权限、开发者镜像（DDI）、部分 iOS 版本的隧道
          └─ 测试自动化 / WebDriverAgent（无障碍树、手势）
```

调查时先确定任务需要哪一层，不要因为某个高级工具具备更多功能，就要求用户完成不必要的准备。

## 产品需要的能力

| 能力 | 当前路径 | 其他路径的地位 |
|------|----------|----------------|
| 设备发现、连接 | USB 多路复用与配对 | 必需能力，无可跳过 |
| 页面、文件夹、图标结构 | `getIconState` | 无障碍树、图像识别是历史回退研究 |
| 应用图标 | SpringBoard 图标服务 | 整屏截图不是当前编辑的必需输入 |
| 修改布局 | `setIconState` 整体写入 | WDA 手势、人工引导未接入当前自动回退 |

上游早期文档曾认为“写入必须依赖自动化层”，后来被 `setIconState` 的真实验证纠正。不要继续以该旧假设决定架构。

## 写入路径及限制

`setIconState` 是经过逆向工具访问的服务接口，不应描述成 Apple 面向第三方公开承诺稳定的布局 API。

| 路径 | 性质 | 项目定位 |
|------|------|----------|
| `setIconState`，SpringBoard 服务 | 将整份 plist 布局发回设备，需配对 | 当前主路径；上游有历史实测，具体设备会话仍要原样写回校验 |
| WDA/XCUITest 手势重放 | 模拟用户操作，速度和稳定性受界面影响 | 仅条件性回退研究，未自动启用 |
| 受监督设备与主屏幕配置描述文件 | 可管理布局；准备条件可能涉及设备擦除和管理工具 | 企业、展台等场景的研究方向，不适用于普通家庭用户的默认流程 |
| 人工引导 | 应用给出步骤，用户在设备操作 | 历史建议，不应声称当前已提供 |

原样写回校验会真实写入设备，因此必须先取得明确确认并保存合格备份。应用编辑需要本会话有效的写入验证标记：普通流程通过原样校验建立；另行确认的同设备合格备份恢复，若读回比较通过，也可建立。新读取或操作失败会使标记失效。校验失败后停止编辑写入，但保留明确确认的恢复路径。

不能保证备份完全撤销所有变化。App 资源库中的应用可能被 iOS 加回主屏幕，恢复也会触发相同行为。重读检查也不等于原子 CAS，检查与写入之间仍有竞争窗口。

历史人工引导的动机是降低开发者模式、签名等准备成本，并应对自动化失效。是否实现该功能，需在主路径确实不适用且用户需求明确时重新立项，不能以“保险”为由自动扩大产品范围。

手势原语和主屏幕编辑模式的历史研究见 `../layout-diff-planner/SKILL.md`；本技能只负责通信通道与前提。

## 读取布局的路径

| 路径 | 可获得内容 | 前提 | 注意事项 |
|------|------------|------|----------|
| `getIconState` | 原始布局、页面、文件夹及项目标识 | USB、配对、服务可用 | 当前主要依据；必须保留全部未知字段 |
| WDA 无障碍树 | 标签与结构化坐标 | 自动化环境 | 历史回退，不是当前推荐首选 |
| 截图加图像识别 | 像素、推断网格、匹配或 OCR 结果 | 截图服务或 WDA | 辅助或研究；识别结果不等于可靠身份 |
| 已安装应用列表 | bundle ID、名称及部分元数据 | 安装代理服务 | 补充未放置应用提示，不能替代布局本身 |
| 系统备份解析 | 可能包含历史 SpringBoard 数据 | 创建备份，可能需要解密 | `[未验证]`，不等于当前应用自行保存的布局备份 |

显示名称会本地化、重复或变化，不能作为可靠身份。当前布局优先采用 `displayIdentifier`，缺失时使用已有 `bundleIdentifier`；已卸载但保留图标的应用可能没有 bundle ID，不应因此丢弃。

详见 `references/capture-and-structure.md`。

## 调查顺序

1. 明确目标设备、iOS、所需能力及已有代码证据。
2. 验证基本 USB 发现、解锁与信任，不自动改动设备。
3. 读取布局并建立原始备份，检查结构是否能原样保留。
4. 需要验证写入时，先展示风险，取得确认，执行受保护的原样写回校验；校验前不应用编辑。
5. 只有主路径无法满足任务时，调查替代路径及其用户成本，例如开发者模式、签名、重装周期、管理员权限。
6. 根据路径选择工具并检查许可证。若已确定需要某层，评估读写能否共用它。

原文“先解决写入可行性”的原则是尽早排除架构死路，不是允许跳过连接、只读检查和写入确认。

## 工具调查清单

- [ ] 目标平台是否原生支持。macOS 中文版需核对 Apple Silicon；Windows 版若必须依赖 WSL/虚拟机，会显著增加部署成本。
- [ ] 所需 iOS 版本的支持情况；查阅近期文档、源码及未解决问题。
- [ ] 许可证与实际分发义务，尤其 GPL/LGPL。
- [ ] 能否再分发必要组件；Apple 组件不能在未核对许可时直接打包。
- [ ] 是否需要管理员权限或驱动安装。
- [ ] 维护活跃度、近期提交和发布。
- [ ] 调用方式是库还是外部进程，以及是否需要 IPC。

具体工具见 `references/tooling.md`。

## 连接诊断

将“连接失败”定位到具体阶段：

1. **USB 未枚举**：检查数据线、接口以及系统识别情况。
2. **多路复用服务不可达**：检查 macOS 系统服务或 Windows Apple 组件；不能在 macOS 上照搬 Windows TCP 端口判断。
3. **配对或信任失败**：设备锁定、尚未回应信任、配对记录失效。
4. **目标服务无法启动**：配对完成但 SpringBoard 服务拒绝请求或版本不兼容；不能默认归因于开发者镜像。
5. **历史自动化路径失败**：仅在明确采用 WDA 时检查签名、安装、测试运行、端口转发与隧道。

详见 `references/connection-troubleshooting.md`。

## 用户错误提示

| 内部失败 | 用户提示 |
|----------|----------|
| USB 发现失败 | “未识别到 iPhone，请重新连接 USB 数据线。” |
| 信任未批准 | “请先解锁 iPhone，并在信任提示中选择‘信任’。” |
| 连接服务不可达 | “请重新连接 iPhone，在访达中检查设备；必要时重新启动 Mac。” |
| 多台设备 | “请断开其他设备，或明确指定要操作的 iPhone。” |
| 历史 WDA 路径缺少开发者模式 | 仅在启用该研究路径时提供与实际 iOS 版本相符的设置指引 |
| 历史 WDA 签名失效 | 仅在该路径中提示重新安装对应组件，不能误导主路径用户 |

保留原始诊断信息用于排错，但日志和报告中的标识符应按隐私规则处理；不得要求用户直接公开配对记录。

## 许可与政策边界

- 区分互操作协议研究与绕过内容保护；若候选路径涉及后者，必须单独评估适用性。
- 不擅自再分发 Apple 提供的二进制组件。核对许可后采用用户自行安装或合适的开源实现。
- 核对名称、图标、市场文案中的商标使用。
- 在确定分发形式前整理开源许可证、源码和告知义务。

发现会影响既定分发方案的限制，应及时报告，避免等到打包完成才调整。

## 记录可复现证据

下面第一段是上游历史观察；第二段是待填写的记录模板，不代表已完成新的验证。

### `[历史已确认]` setIconState 行为

iPhone 14、iOS 26.1，2026-08-19：

| 观察 | 结果 |
|------|------|
| 发出的布局 | 原样回传读到的数据 |
| 保留 | 309 个项目，顺序、文件夹内容和该次观察中的 `iconModDate` 均保留 |
| 丢失 | 0 |
| 意外移动 | 0 |
| 新增 | 最后一页末尾增加 4 个应用 |
| 耗时 | 写入约 820 ms，重读约 100 ms |

该次观察显示 iOS 会把仅在 App 资源库中的已安装应用添加到末尾。用户可在 iPhone 上手动“从主屏幕移除”，但恢复布局备份不能自动撤销。后续是否再次添加取决于届时状态，不能把一次样本推广为所有版本的永久保证。

当前比较要求没有丢失、意外移动或内容变化；新增项目单独报告，已确认易变时间字段不作为失败依据。

```markdown
### [已确认] 设备发现
- 工具 / 命令：<实际执行的命令>
- 环境：<macOS 或 Windows 版本>，iOS <版本>，设备 <型号>
- 输出摘录：<经过必要脱敏的实际输出>
- 验证日期：YYYY-MM-DD
- 限制：<复现条件和未验证范围>
```
