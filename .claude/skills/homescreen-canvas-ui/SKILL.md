# 主屏幕画布界面

产品通过电脑屏幕解决“iPhone 一次只能显示一个主屏幕页面”的限制。界面必须直接体现这一价值。

## 当前实现与历史设计

当前实现使用 Python 与 Qt，支持本地 macOS 中文版。布局通过 SpringBoard 服务整体读写，不执行触控手势。下文涉及设备触控坐标、逐图标执行、数分钟计划、部分应用和断点续作的内容是历史手势方案的设计要求，仅在重新评估该回退方案时使用；不能据此声明当前产品具备这些功能。

当前应用先显示连接指南；读取成功后显示多页画布。编辑结果保留在电脑中，只有用户确认并应用后才写入 iPhone。应用编辑要求本会话存在有效的写入验证标记。普通流程由用户明确确认后执行真实的“原样写回校验”来建立该标记；用户另行确认的同设备合格备份恢复，若写后读回比较通过，也会建立该标记。新读取或操作失败使标记失效。校验失败仍保留单独确认的恢复入口。

## 设计起点

用户打开应用是为了**同时看见多个页面，并直接移动图标**。读取成功后，主要界面应当是展开的页面画布，而不是说明或设置；未连接、尚未读取时必须先提供下一步指引。

以下三项要求应同时成立：

| 要求 | 含义 |
|------|------|
| 一眼看清 | 即使有 8 页，也能通过适当缩放理解整体结构；放不下时明确提示放大窗口 |
| 直接移动 | 跨页拖放不需要特殊模式 |
| 知道设备是否已更新 | 不混淆电脑中的编辑与 iPhone 上的实际布局 |

第三项尤其重要。编辑**不会即时写入设备**；否则用户会以为拖动后 iPhone 应立即变化。

## 状态的视觉区分

`observed` 表示设备实际状态，`desired` 表示编辑目标。两者在概念上同时存在；当前代码以原始快照和编辑文档表达这一关系。

| 状态 | 表现 |
|------|------|
| 与设备一致 | 普通显示 |
| 已编辑、尚未应用 | 用边框、标记或色调明确区分，并显示修改列表 |
| 无法识别的项目 `Unknown` | 明确区分，用提示说明原因，禁止移动 |
| 低置信度项目 | 历史识别方案要求使用弱化标记；当前 plist 模型没有通用 `confidence` 字段 |

**“尚未应用的修改 N 项”必须持续可见。** 关闭含未应用修改的窗口前提示用户。

拖放可以立即更新电脑上的画布，以保持操作反馈，但必须继续标记“未应用”，不能让用户误以为设备已更新。

## 坐标系

当前界面涉及画布、页面局部坐标和网格位置。历史触控方案还增加设备物理像素：

```text
画布坐标（应用缩放与平移）
   ↓
页面块坐标（页面局部位置）
   ↓
网格位置（行、列）
   ↓
设备物理像素（仅历史触控方案使用）
```

还要考虑 macOS Retina，以及 Windows 的 125%、150%、175% 等显示缩放。

### 规则

- 坐标转换集中在同一处。重复实现容易导致“偶尔偏移一个位置”的难复现问题。
- 用不同类型区分 `CanvasPoint`、`SlotIndex`、`DevicePoint`；全部使用 `(int, int)` 会掩盖混用。
- 在设计坐标处理时就考虑 DPI，不要仅在 100% 缩放下开发。
- 多显示器之间移动窗口可能改变缩放，应处理相应事件。

## 拖放

### 放下前校验

拖放过程中显示有效目标，避免用户放下后才发现不允许。

检查事项：

- 目标为空，还是会触发插入、交换或顺延。
- 项目是否为可移动的受支持类型；当前不支持编辑的小组件或未知项目不能凭大小猜测放行。
- 程序坞是否有容量，是否接受该类型。
- 拖到文件夹上时，是放入文件夹，还是插到它旁边。

调用 `homescreen-layout-model` 的约束检查。**界面不能另写一套布局约束。** 当前判定集中在 `LayoutDocument`。

### 顺延预览

历史方案以 `allowsGaps` 区分是否压紧布局：不允许空位时，移动一个图标可能导致多个图标顺延，设计要求放下前展示后果。当前实现支持插入和跨页顺延；是否具备完整预览必须以代码与界面实测为准，不能把这一设计要求当成已完成能力。

### 跨页拖放

同时显示多个页面是产品的核心，跨页拖放应当顺畅。已在屏幕中可见的目标不应还要求用户通过自动滚动才能到达。

## 撤销

编辑以可执行、可撤销的命令表示：

- 支持撤销和重做。
- 一次拖放及其引起的顺延、增页、移除空文件夹作为同一个命令撤销。
- 连续微调可以在有明确交互规则时合并。
- **写入后的恢复不是编辑撤销。** 从备份恢复会再次向设备写入整份布局，需要单独确认。

备份不能保证撤销所有 iOS 副作用：仅在 App 资源库中的应用可能重新出现在主屏幕上，恢复备份也无法自动撤销这一行为。

## 应用流程界面

### 当前整体写入流程

读取 → 展示与编辑 → 确认修改及风险 → 重读并检查原始状态是否过期 → 保存并校验备份 → 整体写入 → 等待设备稳定 → 重新读取并比较。

原样写回校验同样是真实写入，必须先显示确认界面。写入期间显示进度并阻止关闭窗口；不能提供会直接打断正在进行的写入的“立即取消”。备份、写入或校验失败后，说明已知结果和可执行的下一步，不能自动重试整体写入。

### 历史手势方案的预演界面要求

下列要求保留供重新评估手势方案时使用，不代表当前功能：

- 总移动次数、预计耗时。
- 修改摘要。
- 排除的项目及原因，例如识别失败或应用不存在。
- 无法执行的项目及原因。
- 部分应用选项，例如仅处理某一页。

### 历史手势方案的进度界面要求

该方案可能持续数分钟，需要显示：

- 当前步骤与总步骤。
- 当前移动的图标名称。
- 预计剩余时间。
- 始终可用的取消请求；取消在安全检查点生效。
- 操作期间不要触碰设备的提示。

### 完成界面

当前界面区分成功与“已写入但需要检查”，列出丢失、意外移动、内容变化以及 iOS 新增项目。恢复也执行写后比较。

历史手势方案还要求区分部分成功、中断，分别列出已完成与未完成操作，并提供根据最新观测重新规划的入口；不能将原始剩余步骤直接继续执行。

## 用户语言

界面使用用户能理解的语言。`usbmuxd`、`lockdownd`、`springboardservices`、`iconState`、`plist` 和 bundle ID 属于内部细节，只有诊断或定位问题确有需要时才展示。

设备错误映射集中在 `src/ipsm/device.py` 的 `_TRANSLATIONS`。新增错误类型在这里处理，避免界面各处各自分支。显示文字通过 `ipsm.i18n` 翻译；macOS 中文版默认简体中文，保留英语、韩语选项。

| 内部情况 | 用户提示示例 |
|----------|--------------|
| 未发现设备 | “未连接 iPhone，请检查 USB 数据线。” |
| 等待信任 | “请在 iPhone 上轻点‘信任’。” |
| 设备已锁定 | “请解锁 iPhone，保持解锁状态后重试。” |
| 未建立信任 | “请在 iPhone 的‘要信任此电脑吗？’提示中选择‘信任’。” |
| 连接服务无法启动 | “准备 iPhone 连接时出现问题，请重新连接后重试。” |
| 读取不完整 | “未能完整读取主屏幕，请重试。为保护原始布局，不能应用此次不完整结果。” |

**每条错误都应给出下一步。** 只说“发生错误”会让用户无从继续。

## 空状态与首次启动

- 未连接设备是常见初始状态，界面应说明连接方式。
- macOS 内置 iPhone 连接服务，使用 USB 数据线并在访达、iPhone 上完成信任即可。Windows 需要 Apple Devices 或 iTunes。无需越狱、开发者模式或 Xcode。
- 读取或首次加载依赖可能需要等待，应显示进度。

## 无障碍与窗口

- 设计时提供键盘操作路径，例如选择、方向移动、确认；具体支持范围须测试后标记，不能把要求当成已实现功能。
- 画布随窗口尺寸调整，多页时允许缩小布局。
- 提供缩放，默认优先显示全部页面；空间不足时说明限制。
- 不仅靠颜色区分状态，同时使用文字或形状。
- macOS 快捷键提示显示 ⌘，避免将 Windows 的 Ctrl 提示直接呈现给 Mac 用户。

## 界面契约

按 `interface-contract` 将界面与下层之间的约定记录在 `_workspace/02_contracts/ui-viewmodel.contract.md`。

至少说明：

- 展示数据及诊断信息。
- 编辑命令格式。
- 约束检查请求与结果。
- 备份、写入、校验的进度和成功、失败事件。
- 取消、关闭窗口以及正在进行设备操作时的处理。

进度事件必须写入契约，否则界面将无法可靠判断后台操作处于哪个阶段。
