## 结论

建议先实现**同一逻辑页内两个普通 App 的离线交换草稿**，并把设备写回作为独立能力推进。Duo 的两页并排是展示方式，不能合成一张 8 列写入页面。小组件、堆叠、文件夹、Dock、页面数量和顺序均固定。

公开资料中有 Duo/iOS 27.2/USB 两次写入后读回成功的作者报告，因此协议路径有可行性线索；它没有证明 HomeSpread、iOS 27.3、当前小组件配置及所有折叠姿态兼容。**本轮保持所有 Duo 写入限制，没有连接或写入手机，也没有重建或替换已安装应用。**

不能通过删除机型黑名单、忽略读回差异或让用户点击一次原样写回来代替适配。原样写回也是整份写入，可能改变读入接口没有返回的状态。

## 关键证据与缺口

固定版本、日期与原始链接见 [公开协议证据](DUO_PROTOCOL_EVIDENCE.zh-CN.md)。以下分别记录资料结论和产品决策：

| 事实或线索 | 证据范围 | 方案要求 |
|---|---|---|
| Duo/iOS 27.2 有读写成功报告 | 第三方自述，仅两次写入，没有完整组件/姿态验收 | 作为可行性线索，不开放当前 iOS 27.3 写入 |
| `getIconState` 返回 list，而其它实现写 `{buttonBar, iconLists, ignored}` | 开源实现及 iOS 27.0 报告 | 将读取快照、编辑草稿和候选协议载荷分开，不能原样套用根结构 |
| 原始布局不含完整的资源库排除清单 | 多个工具的源码和限制说明 | 不能把 `ignored=[]` 当默认值；清单缺失或不完整时拒绝生成可执行计划 |
| 卸载占位应用、隐藏系统项和隐藏网页快捷方式增加清单复杂度 | 源码存在不同处理策略，部分状态不能通过 USB 获取 | 明确查询范围、完整性收据和无法观测的状态；不能任选一个过滤规则后称其完整 |
| 小组件顶部选择/内部配置可能在设备写入时重置 | 其它机型及 iOS 27.0.1 的报告；不是 Duo 专属实测 | 字典原样保留仍不够。禁止把缺失 ID 当通配，禁止静默忽略选中项变化 |
| 独立组件 ID 别名补丁有有限先例 | Rejig 的其它机型测试；堆叠配置仍有未验证部分 | 只作为单独研究的协议转换，不改原始备份、不将独立组件规则套用堆叠 |
| 手机原生空隙、隐藏页可能不在导出中，整体写入会影响未编辑页面 | 第三方限制及实机报告 | 顺序读回不能证明真实坐标与页面可见性保留；需要独立画面对照 |
| 当前 SDK 发送后等待回复，未为该调用设置独立超时 | 固定 `pymobiledevice3 11.54.0` 源码 | 无回复不等于未写入；区分发送、未确认和验证结果，不自动重发或恢复 |

“App 资源库回填永远不可避免”不是本研究的结论。当前 HomeSpread 没有实现上述 `ignored` 候选路径，也没有验证其完整性，所以仍必须保留既有副作用提示。

## 本轮已完成的离线工作

### 1. 受限编辑规划器

`research/duo_planner.py` 只处理内存中的 plist 数据，使用标准库，无文件、网络、USB、SDK、GUI或设备操作接口。

```python
analyze_layout(raw) -> dict
plan_swap(raw, page, index_a, index_b) -> list
validate_swap(origin, candidate, page, index_a, index_b) -> dict
```

`page` 是原始顶层数组索引：0 为 Dock，不可选择；1 开始为逻辑主屏幕页。两个项目索引从 0 开始，并且必须指向同一页内可区分的普通 1×1 App。即使显示标识符重复，也通过具体位置和完整原文区分；完全相同、无法观察到变化的交换被拒绝。

独立校验器不相信规划器的成功标记，逐项检查：

- 改动位置必须正好是用户意图中的两个位置，内容必须互换，而非重建。
- 其它每个位置的完整对象不变，包括未理解的字段、二进制数据、日期和布尔类型。
- Dock、页面边界、文件夹原文、组件尺寸、堆叠成员及顺序、当前选择、建议开关全部不变。
- 条目多重集不变，不丢失、复制或悄悄插入应用。
- 模拟网格中的组件占位和锚点不变；这只证明模型性质，不代表真实 iOS 坐标。
- 候选二进制 plist 序列化后仍保持相同类型和值。Python 的 `True == 1` 不会绕过校验。

不支持的结构、空占位、组件尺寸、容量溢出、Dock 修改、文件夹修改、组件移动、跨页移动和额外字段改变均被拒绝。模型采用本地已知的 4×6 逻辑页和 3×3 文件夹页，不扩展成任意设备通用算法。

### 2. 协议载荷形状实验

`research/duo_envelope.py` 只研究 list 到候选 dict 的包装和二进制序列化。调用者必须明确提供一个**候选**排除清单；缺失时抛出 `EvidenceMissing`，不会自动使用空列表。

测试只使用虚构清单，核对重复/空标识符拒绝、显示标识符与包标识符同时参与冲突检查、完整字段保留及对象拷贝隔离。组件扩展标识符不会被当作普通桌面 App。该分类实验不裁决隐藏系统项应该怎样进入 `ignored`。

所有返回对象的 `can_send` 恒为 `False`。本轮没有根据个人备份生成真实设备的字典写入载荷，也没有实现实际安装清单采集或发送器。

### 3. 验证结果

- 研究相关测试 **107 项通过**，其中独立边界检查 42 项；完整仓库 **371 项测试、383 项子测试通过**，测试进程正常退出。
- 合成测试包含同页候选交换及逆向还原、错误意图、重复标识符、日期/字节/布尔类型破坏、组件选择变化、Dock/文件夹篡改和未知结构拒绝。
- 已对获授权的现有备份穷举全部符合范围的候选交换并独立校验，全部通过。本机报告留在忽略的 `build/private-duo-study-result.json`，不公开原始布局、应用名、设备标识或逐页清单。
- 重新读取原始备份文件后，文件字节 SHA-256 未改变。规划器中的 `raw_sha256` 是规范化二进制 plist 的值摘要，不能一般化地冒充原文件字节摘要，两者分别核验。
- 已确认生产 `write_policy` 对 Duo、小组件的拒绝仍生效，即使研究草稿满足全部局部约束，也不能通过当前设备写入入口。

详细独立检查见 [离线 QA 报告](DUO_OFFLINE_QA.zh-CN.md)。研究模块不被运行中的应用导入；未来源码归档会包含研究源码以便重跑测试，但不将它加入应用的可执行依赖。

在仓库根目录可重跑虚构数据研究测试，无需连接手机：

```sh

```

## 编码层还需要单独处理

本地备份采用二进制 plist。当前 SDK 的 `build_plist` 和 `send_plist` 默认使用 XML，见固定版本的 [编码实现](https://github.com/doronz88/pymobiledevice3/blob/48f0215836ee1349b75464ddb08ad6aebb1e74f4/pymobiledevice3/service_connection.py#L54-L67)。

离线实验确认，当前备份经过 XML 编解码后，部分 `iconModDate` 的秒以下精度丢失。测试数据从未发往设备。二进制无损往返不能证明现有网络编码也无损；也不能直接改成二进制发送并假设 iOS 接受。

后续发送适配须明示 wire format、记录允许变化的易变字段，并用严格读回区分时间归一化和真正内容损坏。组件选中项、成员配置、未知字段不能因为方便而加入忽略清单。

## 后续实施顺序与验收门槛

| 阶段 | 具体实现 | 通过条件 | 是否涉及手机 |
|---|---|---|---|
| A：离线草稿界面 | 在原始快照旁建立独立草稿；只开放本轮验证的同页 App 交换，展示两个改动位置；保存为明确标注的研究草稿 | 使用本轮规划器和独立校验器，撤销/重做不改变基线；无设备调用；不能被误当成恢复备份 | 不涉及 |
| B：只读证据包 | 设计设备型号/iOS 构建号、布局版本、网格、方向、组件配置和资源库清单的采集收据；明确系统项、卸载占位、隐藏网页快捷方式等未知信息 | 查询失败、范围不全、基线变化或无法解释的状态均为缺失证据；不能用空结果代替完整结果 | 实际采集另行明确范围；本轮未执行 |
| C：离线写入适配模拟 | 分离原始快照、编辑意图、协议转换与候选请求；模拟超时、断线、无回复和不一致读回 | 所有失败分支停止发送；不得自动再次写入；严格比较组件数据，输出具体缺失字段与未验证状态 | 只用假传输对象 |
| D：受控真机实验方案 | 固定设备/iOS 构建、候选请求摘要、唯一操作、预期副作用、停止条件和恢复局限 | 实验方案可审阅，且得到针对这次真实写入的明确授权。优先使用可接受布局变化的测试设备；个人设备不能假定可无损恢复 | 需要后续授权，本轮不执行 |
| E：有限能力开放 | 记录特定设备/系统/协议格式/操作类型的验证结果，只为通过的组合开放能力 | 读回、画面、堆叠选择/配置、页面可见性与资源库成员检查均满足声明的支持范围；系统或配置改变使资格失效 | 只有通过 D 后才可能开放 |

阶段 D 不能只看一个“通过”布尔值。必须分别判定：导出字段是否一致、组件真实配置是否一致、真实位置与隐藏页是否一致、资源库是否出现回填，以及哪些信息仍无法观测。若有任一项无法满足承诺，就缩小支持声明或继续禁用，不能通过忽略差异把结果变绿。

## 拟议写入状态处理

```text
本地草稿验证 → 当前状态/证据检查 → 合格备份 → 单次发送开始
                                                ↓
                                  收到回复 或 未收到可靠回复
                                                ↓
                                    新连接上的有限次只读核对
                                                ↓
                       导出字段匹配 / 明确不一致 / 仍无法确定
```

发送开始后出现超时或断线，应显示“可能已写入，尚未确认”，阻止其它编辑写入。不因为没有回复就重新发送，不自动写回备份。导出字段匹配仍不等于完整桌面状态已验证；画面和组件配置的额外证据必须独立呈现。

目前最具体、可独立推进的下一项是阶段 A：让用户在完全断开的离线草稿上做受限编辑并查看差异，同时保持已安装应用的 Duo 设备写入禁用。
