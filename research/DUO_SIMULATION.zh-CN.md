# Duo 写回适配：假设备状态机验证

日期：2026-11-13。实现为 `research/duo_simulator.py`，测试为 `tests/test_write_simulator.py`。这是阶段 C 的纯内存故障模拟，不是手机发送器；本轮没有读取或写入手机，没有运行 `--roundtrip`。

## 已实现的边界

`simulate()` 只接受明确的 `Scenario` 数据对象，内部构造不可派生的 `FakeTransport`。调用方不能传入设备桥、SDK 客户端、网络连接或发送回调。所谓“发送”只是将一个 Python 值复制到假设备的内存状态；“新连接”是每次只读核对分配的递增逻辑编号，没有 socket、USB 或真实连接。

输入先验证原始 plist 类型，拒绝带自定义拷贝钩子的 Python 对象。模块只使用标准库、纯草稿规则与离线载荷包装实验。没有文件读取、SDK 导入或设备操作接口。命令行只选择内置虚构情景，不接受个人文件或设备参数。

所有结果的 `can_write` 和 `fully_verified` 恒为 `False`。即使假设备读回完全一致，也只返回 `EXPORTED_FIELDS_MATCH_ONLY`，并继续列出隐藏页可见性、手机原生空隙、组件真实配置和 Duo 姿态行为等未验证内容。

## 模拟流程

```text
虚构身份匹配 → 验证草稿意图 → 原始快照未过期 → 虚构清单覆盖检查
                                                     ↓
                                              假备份校验
                                                     ↓
                                               单次内存发送
                                                     ↓
                                      有回复 / 发送结果不确定
                                                     ↓
                                      最多 5 次独立只读核对
                                                     ↓
                        导出字段匹配 / 明确差异 / 最终仍无法确定
```

身份、草稿、过期快照、清单覆盖或备份任一检查失败，模拟发送次数为 0。发送开始后，超时、断线或无可靠回复记录为不确定状态，不能推断设备未改变。允许继续进行有上限的只读核对，但发送尝试最多一次，自动恢复次数永远为 0。

若较早读回有差异，而最后一次读取又不可用，最终结果为 `UNCERTAIN`，保留先前的差异诊断，不把旧观察伪装成设备最终状态。若迟到的读回匹配，也只升级到导出字段匹配，不能升级成完整兼容性确认。

## 载荷与清单实验

虚构库存包含 User、System、卸载占位 App 和单独列明的隐藏网页快捷方式。每个查询分别记录 `observed`、`failed` 或缺失状态，以及是否完整；失败的空结果不能当作成功的空清单。

完整标记和占位覆盖必须是字面布尔值 `True`，不能用整数 1 冒充。占位 ID 必须属于相应查询结果，User/System 类型冲突不能静默去重。候选清单与桌面 App 的显示标识符、包标识符都对照，避免同一可见 App 被另一个 ID 错误加入排除清单。

这些是**虚构世界中的一致性规则**，不证明真实 USB 查询能得到完整资源库、隐藏网页快捷方式或应采用哪一种隐藏系统项策略。实际证据缺失仍应阻止发送。该模拟没有解决公开研究中已记录的可观测性缺口，详见 [协议证据](DUO_PROTOCOL_EVIDENCE.zh-CN.md)。

## 内置情景结果

共 24 个内置情景：

| 结果 | 数量 | 示例 |
|---|---:|---|
| `BLOCKED` | 10 | 清单缺失、失败空清单、未包含卸载占位、隐藏网页快捷方式未知、身份不同、快照过期、备份失败或损坏 |
| `UNCERTAIN` | 4 | 发送超时后假状态已改变但无法读回、发送后断线、读取持续失败、差异后读取不可用 |
| `MISMATCH` | 7 | 未发生预期交换、组件选中项丢失、堆叠顺序变化、布尔值变整数、不透明字节变动、日期精度丢失、资源库应用回填 |
| `EXPORTED_FIELDS_MATCH_ONLY` | 3 | 正常回复后匹配、无回复后匹配、第一次未稳定但后续匹配 |

比较器检查完整的类型和值，不忽略组件选中项、堆叠成员、不透明字段或日期精度。诊断只列字段路径及变化类别，不把应用清单和组件内容原文写入模拟报告。

## 测试与复现

本模块的 **69 项测试通过**，进程退出码 0。覆盖所有内置情景、发送/恢复计数、读取上限、每次核对的新逻辑连接、双 ID 冲突、真实空清单与失败空结果区分、输入不变、自定义对象和任意适配器注入拒绝等。

在仓库根目录运行：

```sh
.venv/bin/python -m pytest -q tests/test_write_simulator.py
PYTHONPATH=src:. .venv/bin/python -m research.duo_simulator --all
PYTHONPATH=src:. .venv/bin/python -m research.duo_simulator --scenario send_timeout_after_side_effect
```

## 验证局限

超时和断线由离散故障情景驱动，没有等待真实时钟、操作系统连接或 SDK 协程，因此这些测试证明的是状态处理及单次发送约束，不证明真实异步取消、网络超时或 iOS 行为。备份同样只在内存中序列化校验，实际磁盘安全由现有备份与文件测试覆盖。

将来若实现真实适配器，必须另行验证发送边界、独立只读连接、取消/超时、设备归属和完整性；不能把这个模拟器替换一个传输参数就直接对手机运行。本轮没有改变生产 Duo 写入限制。
