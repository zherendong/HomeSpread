# Duo 离线编辑研究：独立验收

日期：2026-11-13。范围：`research/duo_planner.py` 的受限编辑草稿、`research/duo_envelope.py` 的候选字典载荷，以及它们与现有写入拒绝策略的边界。本轮没有连接手机、读取新的设备资料、写入布局、运行 `--roundtrip`，也没有修改已安装应用或解除 Duo 写入限制。

## 结果

- 研究测试：**107 项通过**，其中 `tests/test_duo_research_boundaries.py` 的 **42 项**为独立边界与反例检查。
- 全量回归：**371 项测试、383 项子测试通过，0 项失败，进程退出码 0**，用时 7.86 秒。
- 唯一警告来自既有 Qt `QDragEnterEvent` 测试构造器弃用提示；没有测试跳过或退出挂起。
- 测试使用虚构的 `example.*` 标识符、日期、二进制字段和小组件内容，不把个人备份或截图作为仓库测试样本。

执行命令：

```sh
QT_QPA_PLATFORM=offscreen \
HOMESPREAD_DATA_DIR="$PWD/build/duo-research-qa-data" \
HOMESPREAD_CACHE_DIR="$PWD/build/duo-research-qa-cache" \
.venv/bin/python -m pytest -q
```

测试证明受检查的本地数据约束成立，**不证明 iOS 接受候选载荷，也不授权写入设备**。

## 独立边界检查

| 边界 | 通过的检查 |
|---|---|
| 操作范围 | 只交换同一逻辑页中两个普通 1×1 App 的完整原始对象；拒绝 Dock、组件、文件夹、相同位置、越界、负数及布尔索引。 |
| 完整内容保留 | 除两个明确端点外，所有位置按类型敏感的二进制 plist 比较；组件原文、堆叠顺序、成员参数、所选成员、建议开关、文件夹名称和内容均不能改变。 |
| 隐蔽类型变化 | 将原始 `True` 改成 `1` 虽然在 Python 中相等，仍会被拒绝；日期微秒和不透明二进制字段也不能被截断或改写。 |
| 身份与重复 | 使用页面和条目索引标识具体出现位置。重复显示标识符但载荷不同的条目必须完整互换，不能通过重复或覆盖一个对象伪装为交换。两个二进制载荷相同的端点被视为无可观察变化而拒绝。 |
| 错误意图 | 候选符合另一个交换操作，但不符合本次声明的两个端点时拒绝。增加第三处修改、改其它页、增删页或丢掉端点时拒绝。 |
| 对象隔离 | 候选与原始快照及另一个草稿没有共享可变载荷；修改返回草稿不会污染原始数据或其它草稿。 |
| 模拟几何 | 两个同尺寸项目交换后，按原始数组位置记录的跨度、占用格数、组件及文件夹锚点不变；该结论只针对 4×6 行优先模型。 |
| 载荷封装 | 原始 list 快照与 `{buttonBar, iconLists, ignored}` 候选字典不是同一种输入。编辑器拒绝把字典载荷悄悄当成原始快照。封装研究要求显式提供候选排除清单，不读取设备来补齐它。 |
| 排除清单冲突 | 当前显示 App 的 `displayIdentifier` 和 `bundleIdentifier` 都参与保守交叉检查；任一标识符同时出现在 `ignored` 时拒绝。 |
| 传输能力 | 研究模块只导入列明的纯数据标准库，不导入应用设备桥、SDK、socket、subprocess、网络客户端、动态执行或 GUI；研究结果的 `device_write_supported`/`can_send` 始终为假。 |
| 生产隔离 | 即使草稿完全通过离线验证，现有 `write_policy` 仍拒绝 Duo，含组件的草稿也仍被拒绝；研究成功不会转换成 `write_verified` 或可发送许可。 |
| 报告隐私 | 分析报告包含计数、索引、模拟几何和摘要，不包含测试样本中的应用名称、标识符、文件夹名称或不透明内容。 |

## 审查发现与修复

1. **候选排除清单的双标识符遗漏。** 最初的封装研究只收集 `displayIdentifier` 或 `bundleIdentifier` 中的一个值；当两者不同且排除清单使用另一个值时，显示中的 App 与排除清单冲突未被发现。独立反例先失败，修复为同时收集两个有效值后通过。此代码没有发送能力，没有实际设备影响。
2. **源码包范围。** 主程序的源码归档原先收集新增测试却不收集 `research/`，后续重新构建会造成归档里的测试缺少研究模块。已将研究文件纳入源码 ZIP 的白名单；没有把研究模块接入运行时、UI、设备桥或写入入口。本轮未重建或安装应用。
3. **不能把类型宽松比较当作保真。** 研究校验采用规范化二进制 plist 比较，不使用普通 Python `==` 作为唯一证据。独立测试覆盖布尔/整数、日期与字节差异。

## 离线能够证明与不能证明的内容

`analyze_layout.raw_sha256` 是对规范化序列化后的值计算的摘要，**不一定等于原始 `.plist` 文件的字节 SHA-256**。主任务读取已有备份时，仍需独立检查文件字节摘要没有改变。摘要只用于一致性，不是加密、数字签名或设备归属认证。

编辑草稿可以证明：基于所提供快照，只有两个指定 App 载荷互换，其余已返回数据不变。它无法证明调用者提供的是最新设备状态；未来实际执行仍需要设备身份绑定、当前布局重读、与草稿基准匹配及不可绕过的能力检查。读取与写入之间仍没有系统级原子比较交换保证。

4×6 行优先排布只能证明模型内的锚点不变。它不能发现或保留接口未返回的自由摆放空隙、隐藏页面、Focus 页面可见性或其它折叠姿态状态。同页 1×1 交换也会通过整份布局写入接口作用于全局，不能将“小修改”理解为“只影响两个图标”。

候选封装只验证包装、序列化和解包保留已提供数据。显式传入 `ignored` 不代表清单完整，空清单也不代表手机上没有资源库专属 App、卸载占位 App 或隐藏网页快捷方式。`can_send=False` 不应被未来集成代码忽略。

## 公开协议证据的验收含义

完整来源见 [公开协议证据](DUO_PROTOCOL_EVIDENCE.zh-CN.md)。本报告区分两条证据，不能合并成“Duo 已通过组件保留验证”：

- [ios-homescreen PR #3](https://github.com/YakupEmreYerli/ios-homescreen/pull/3) 的 Duo/iOS 27.2 两次写入是来源作者自述，未给出组件操作、堆叠设置、隐藏页和空位的完整验收细节；本次没有复现。
- 该项目固定提交的[比较器](https://github.com/YakupEmreYerli/ios-homescreen/blob/97649547dbc44295e451c6bf130a87404481e10c/src/ios_homescreen/state.py#L311-L346) 明确省略 `userSelectedElementIdentifier`，源码把丢失此字段的观察限定到 iOS 27.0.1。其[限制说明](https://github.com/YakupEmreYerli/ios-homescreen/blob/97649547dbc44295e451c6bf130a87404481e10c/README.md#L415-L435) 也披露组件选择重置。**这不是 Duo 专属实测**，但足以说明“第三方比较通过”不能当作完整配置保留的证明。

本轮研究比较器不会为了通过测试而忽略组件选择、成员顺序或配置载荷变化；一旦真实读回出现这些变化，未来实现应报告失败或不完整，不能把缺失字段当作任意值通配。

## 后续真实验证的前置条件

以下是后续独立阶段的验收门槛，不是本轮授权，也不是要求现在操作手机：

1. 明确受支持的设备型号、iOS 完整构建、读写格式、组件种类和页面配置；不能仅按“Duo”型号全局放行。
2. 先解决信息覆盖：未显示应用、卸载占位、隐藏网页快捷方式、空隙与隐藏页面。不能取得的状态须明确限制，不可用一个成功的序列化测试替代。
3. 在另行授权的具体试验中，发送前拥有同设备、可独立读回验证的原始备份；记录草稿基准摘要、两个精确端点、载荷转换及风险。优先使用有可控测试布局的非日常设备。
4. 区分“未发送”“已发送但无回复”“读回不一致”“完整验证通过”。无回复不自动重发，失败不自动恢复；恢复本身需要另一份明确计划和授权。
5. 验证严格比较器以及接口看不到的状态：组件配置、堆叠当前成员、所有成员参数、全页实际位置、页面可见性、资源库回填，以及折叠/展开视图。API 回复或仅数组次序一致不算全部通过。
6. 只有这些证据达到已定义验收范围后，才能评审是否引入精确能力标记。现有 Duo/组件写入拒绝在本轮始终保留。
