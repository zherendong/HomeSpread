# HomeSpread

*Mobile layout manager for iOS*

여러 페이지로 흩어진 iPhone 홈화면을 PC 한 화면에 펼쳐 보고, 드래그로 정리하는 Windows 앱.

> **이름과 부제를 나눠 둔 이유.** Apple 상표 지침은 자기 제품 **이름 안에**
> `iOS`·`iPhone` 을 넣는 것을 금지하고, 호환성 표기는 이름 아래 부제로만 허용한다.
> 스토어 심사에서 걸리는 자리도 "앱 이름" 칸이다. 그래서 이름은 `HomeSpread`,
> 호환성 표기는 부제(`Mobile layout manager for iOS`)로 두고, 코드에서는 둘 다
> `src/ipsm/product.py` 한 곳에서만 선언한다.

## 지금 어디까지 되어 있나

**전 구간 실기기 확인 완료 · 폴더 하나로 배포 가능**

읽기 → 펼치기 → 드래그 편집 → 백업 → 쓰기까지 실제 iPhone 에서 확인되었다
(아래 "실기기 확인 결과"). 두 번의 적용에서 **잃은 항목 0, iOS 가 덧붙인 항목 0**,
두 번째 적용에서는 보낸 내용과 기기가 되돌려준 내용이 완전히 같았다.

파이썬이 없는 PC 를 위해 **실행 폴더 하나**로도 묶을 수 있다 (`build_exe.bat`).

## 어떻게 동작하나

비탈옥 iPhone에도 `com.apple.springboardservices` 라는 lockdown 서비스가 있고,
여기에 `getIconState` / `setIconState` 가 있다. 홈화면 배치 전체를 plist 하나로 읽고,
plist 하나로 되돌려 쓴다. 탈옥·개발자 모드·Xcode·WebDriverAgent 모두 필요 없고,
USB 연결과 "신뢰" 한 번이면 된다.

대신 **`setIconState` 는 부분 수정이 아니라 전체 덮어쓰기다.** 우리가 이해하지 못해
빠뜨린 요소(위젯, 새 iOS 기능)는 그대로 사라진다. 이 프로젝트의 설계는 대부분
그 사실 하나에서 나온다:

- 원본을 해석하지 않고 그대로 보존한다 (`iconstate.py`)
- 모든 쓰기는 백업을 만든 뒤에만 한다. 백업 실패는 곧 쓰기 중단이다 (`backup.py`)
- 편집 기능을 켜기 전에 **항등 왕복 시험**을 통과해야 한다 (`probe.py`)

되돌리기가 가능하다는 것도 여기서 나온다. 직전 상태를 그대로 다시 쓰면 완전히 복구된다.

## 준비

1. **Apple Devices 앱 또는 iTunes 설치** — Windows가 iPhone과 통신하는 데 필요하다.
   (Microsoft Store의 "Apple Devices" 권장)

   > 앱을 켜면 **시작 안내판**이 먼저 뜬다. 이 준비물이 지금 갖춰져 있는지 스스로 보고,
   > 없으면 Microsoft Store 로 데려간다. 확인하는 것은 **`127.0.0.1:27015` 가 열려 있는가**
   > 한 가지다 — Apple 쪽 구성요소가 USB 를 맡으면서 여는 자리이고, 무엇이 열었든
   > 상관없다. 설치 폴더가 있는지도 보지만 그것은 "설치는 됐는데 아직 안 떴다"와
   > "아예 없다"에 **할 말을 고르기 위한 짐작일 뿐**, 막는 근거로는 쓰지 않는다.
   > 옆에서 설치를 끝내면 안내판이 3초 안에 스스로 바뀐다.

2. 설치 스크립트 실행 — 탐색기에서 `install.bat` 을 더블클릭하거나, 명령 프롬프트에서:

   ```
   install.bat
   ```

   PowerShell 창을 쓰고 있다면 `.\install.ps1` 도 된다. 다만 **명령 프롬프트(cmd)에서는
   `.\install.ps1` 이 아무 일도 하지 않는다** — cmd 는 `.ps1` 을 실행하지 않고 연결 프로그램으로
   열기만 한다. 그래서 어느 창에서든 되는 `install.bat` 을 둔 것이다.

   `pip install pymobiledevice3` 를 직접 하면 `lzfse` 확장 빌드에서 멈춘다
   (Visual C++ 빌드 도구 요구). `lzfse` 는 펌웨어 압축 해제용이라 홈화면 작업에는
   쓰이지 않으므로, 이 스크립트는 그것만 빼고 설치한다.

## 실행

iPhone을 USB로 연결하고, **잠금을 해제한 상태로** 둔 뒤:

> **최초 1회는 반드시 잠금이 풀려 있어야 한다.** iOS 는 잠긴 기기와의 페어링을 거부한다
> (프로브가 "iPhone이 잠겨 있어 연결할 수 없습니다" 로 알려준다). 잠금을 푼 채로 케이블을
> 다시 꽂고, iPhone 화면의 **"이 컴퓨터를 신뢰하시겠습니까?"** 에서 **신뢰**를 누른 뒤
> (암호를 한 번 더 물어본다) 다시 실행한다. 한 번 신뢰하면 다음부터는 필요 없다.

```
run_app.bat
```

파이썬이 설치되지 않은 PC 라면, 만들어 둔 **`HomeSpread\` 폴더째** 복사해 원하는
자리에 두고 그 안의 `HomeSpread.exe` 를 더블클릭한다. 준비 단계(`install.bat`)도 필요
없다. 처음 실행하면 exe 옆에 `logs\` `backups\` 폴더가 자동으로 만들어지므로,
**쓰기 권한이 있는 폴더**(바탕화면·문서 등)에 둔다. Program Files 처럼 쓸 수 없는 곳에 두면 앱이 그 사실을
알리고 시작하지 않는다 — 백업을 남길 수 없는 상태로는 기기에 쓰지 않기 때문이다.

자료를 어디에 두는지는 `src/ipsm/paths.py` 한 곳이 정한다. 규칙은 **잃으면 안 되는 것과
다시 만들 수 있는 것을 가르는 것**이다 — `backups\` `logs\` `settings.json` 은 위에서 말한
자리에 남고(Microsoft Store 로 설치한 경우에만 `문서\HomeSpread\`, 설치 폴더에 쓸 수 없기
때문이다), 아이콘 그림은 Windows 임시 폴더에 둔다. 어느 자리를 골랐는지는 실행할 때마다
`logs\` 첫 줄에 적힌다.

실행 폴더를 새로 만들려면:

```
build_exe.bat
```

(`dist\HomeSpread\` 로 나온다. 옵션과 그 이유는 `HomeSpread.spec`.)

단일 파일이 아니라 폴더인 이유는 시간이다. 단일 exe 는 실행할 때마다 자기 안 72MB 를
임시 폴더에 풀고, 그 시간이 **매번** 붙는다 — 실측 21초 중 16.5초가 그것이었다. 폴더로
내면 풀 것이 없어 **2.3초**다. 그래도 창이 뜨기 전 몇 초는 남으므로, 그 자리는
PyInstaller 부트로더가 띄우는 시작 그림이 채운다 (0.3초에 뜬다).

홈화면을 읽어 와 페이지를 한 화면에 펼친다. 처음에는 아이콘이 글자 타일로 보이는데,
도구모음의 **아이콘 받기** 를 한 번 누르면 기기에서 받아 온다 (300개에 약 8초, 다음부터는
받아 둔 것을 쓴다).

아이콘을 끌어 옮기고, 폴더는 두 번 눌러 연다. 폴더 한가운데에 놓으면 폴더 안으로,
옆에 놓으면 그 자리에 끼운다. 오른쪽 곁판에 바뀐 내용이 쌓이고, **적용** 을 누르면
확인 화면을 거쳐 백업한 뒤 기기에 쓴다.

### 묶기(폴더 만들기)와 이름 바꾸기

두 가지 방법이 있고 결과는 같다.

- **앱 위에 앱을 겹쳐 놓는다** — iPhone 에서와 같다. 아이콘 한가운데에 놓으면 묶음이
  되고, 가장자리에 놓으면 그냥 그 자리에 끼운다.
- **여러 개를 골라 묶기(Ctrl+G)** — Ctrl 을 누른 채 아이콘을 눌러 여럿을 고른다.
  페이지를 건너서도 고를 수 있다. 고른 순서가 아니라 **화면에 보이는 순서**로 담기고,
  새 묶음은 첫 항목이 있던 자리에 놓인다.

묶고 나면 이름을 묻는다. 이름은 나중에 **F2** 또는 폴더를 열었을 때의 **이름 바꾸기**
단추로 언제든 바꿀 수 있다. 원래 있던 폴더도 마찬가지다.

묶음이 꽉 차면 **페이지가 한 장 더 펴진다** — iPhone 에서와 같다. 꽉 찬 페이지의 **자리를
겨눠 놓으면 뒤가 한 칸씩 밀리고, 넘친 마지막 항목이 다음 페이지 맨 앞으로 간다.** 끝에
붙이려고 뒤쪽 빈 곳에 놓았을 때는 아무도 밀지 않고 빈자리를 찾아 넣는다 — 겨누지도 않은
항목이 페이지를 넘어가면 무엇을 옮겼는지 알 수 없어진다. 묶음 안의 **페이지가 다 비면 그
페이지도 없어진다.** 반대로 **마지막 하나를 꺼내면 빈 묶음은 그 자리에서 없어진다.** 빈 묶음을 그대로 기기에 보내면 iOS 가 그것을
지우면서 뒤따르던 항목이 전부 한 칸씩 밀리는데, 그러면 적용 후 확인 화면이 "손실"과
"의도치 않은 이동"을 잔뜩 보고한다. 실제로 잃은 것이 없어도 사고처럼 보인다.

페이지가 펴지는 것도, 묶음이 없어지는 것도 **되돌리기 한 번**이면 함께 되돌아간다.

묶을 수 없는 경우는 그 자리에서 이유를 말한다 — 묶음끼리는 묶을 수 없고(iOS 가 폴더
안의 폴더를 지원하지 않는다), 이미 묶음 안에 있는 것은 먼저 꺼내야 하며, 우리가
해석하지 못한 항목(위젯 등)은 안전을 위해 건드리지 않는다.

연결만 확인하고 싶으면 진단 프로브를 쓴다:

```
run_probe.bat
```

읽기만 한다. 기기에 아무것도 쓰지 않는다. 결과에서 홈화면 구성이 제대로 보이면:

```
run_probe.bat --roundtrip
```

읽은 배치를 **한 글자도 바꾸지 않고** 그대로 다시 쓴 뒤 재확인한다.
실행 전 확인 질문이 있고, 직전 상태는 자동으로 백업된다.

| 결과 | 의미 |
|------|------|
| 통과 | 사라진 것도 움직인 것도 없다. 편집 기능을 만들어도 안전하다. |
| 실패 | 항목이 사라졌거나 자리가 바뀌었다. **편집 기능을 만들지 않는다.** |

판정 기준이 "완전 동일"이 아닌 이유는 iOS 의 동작 때문이다. **홈화면에 없던 앱(앱
라이브러리에만 있던 앱)을 iOS 가 마지막 페이지 끝에 되붙인다.** `setIconState` 에는
"설치됐지만 홈화면에 없음"을 표현할 방법이 없기 때문이다. 눈에 보이고 길게 눌러 "홈 화면에서
제거"로 되돌릴 수 있지만, **백업 복원도 쓰기이므로 이것만은 백업으로 되돌려지지 않는다.**
한 번 붙고 나면 모든 앱이 배치된 상태가 되어 더는 늘지 않는다.

### 실기기 확인 결과 (iPhone 14, iOS 26.1 · 2026-08-19)

항등 왕복 **통과**. 309개 항목이 순서·폴더 내용·`iconModDate` 까지 그대로 보존됐고,
손실 0 · 이동 0. 부작용은 위에 적은 앱 4개 되붙음뿐이었다. 쓰기 820ms, 되읽기 100ms.

### 옵션

| 옵션 | 설명 |
|------|------|
| `--roundtrip` | 항등 왕복 안전 시험 (기기에 씀 · 확인 질문 있음) |
| `--icons` | 앱 아이콘 이미지도 내려받는다 (UI에서 쓸 예정) |
| `--udid <값>` | 기기가 여러 대일 때 지정 |

## 기록되는 것

실행할 때마다 세션 하나가 만들어지고, 덮어쓰지 않는다. 문제 신고 하나가 실행 하나에
대응해야 하기 때문이다. 대신 **최근 20회분만 남기고 오래된 것은 스스로 지운다**
(`logging_setup.KEEP_SESSIONS`). `logs/` 안에서 우리가 지은 이름 모양에 맞는 것만
지우므로, 그 폴더에 따로 둔 파일은 건드리지 않는다. `backups/` 는 지우지 않는다.

```
logs/probe_20260819_143116.log          전 과정 (라이브러리 내부 로그·스택트레이스 포함)
logs/probe_20260819_143116/             그 세션의 원본 산출물 — 받아 온 것이 있을 때만 생긴다
    icon_state_before.plist                 읽은 원본 그대로
    icon_state_before_readable.json         사람이 읽는 형태
    icon_metrics.json                       그리드 수치
    device_info.json                        기기 정보 (UDID는 앞 4자리만)
    unknown_items.json                      우리가 해석하지 못한 항목의 원본
logs/probe_20260819_143116_report.zip   위 전부를 묶은 것 — 문제 신고 시 이 파일만
backups/20260819_143116_probe.plist     이 시점의 홈화면 (복원용)
```

전화번호·계정·전체 일련번호는 기록하지 않는다. UDID는 앞 4자리만 남긴다.
라이브러리 예외 메시지나 스택트레이스에 UDID 가 섞여 나와도, 로그로 나가기 직전에 지워진다.

**문제가 생기면 `_report.zip` 하나만 있으면 된다.** 어느 단계에서 몇 밀리초 만에
무엇으로 실패했는지가 전부 들어 있다.

여기 적힌 것이 전부다 — 밖으로 나가는 것은 없다. 무엇을 읽고 무엇을 남기는지는
`PRIVACY.md` 에 한국어와 영어로 적어 두었고, 프로그램의 **정보 → 개인정보 처리방침**
에서도 같은 글을 읽을 수 있다. 인터넷 없이 도는 프로그램의 방침을 인터넷에서만
읽게 할 수는 없어서 원문을 함께 싣는다.

## 홈화면을 되돌리려면

`backups/` 의 `.plist` 파일이 그 시점의 홈화면 전체다. 복원은 `backup.py` 의
`restore()` 가 하며, 복원 직전 상태도 다시 백업한다.

## 구조

| 파일 | 역할 |
|------|------|
| `src/ipsm/logging_setup.py` | 세션 로그와 산출물 |
| `src/ipsm/device.py` | pymobiledevice3 를 감싸는 유일한 계층 · 오류를 사용자 언어로 번역 |
| `src/ipsm/iconstate.py` | 레이아웃 해석 (원본 보존이 제1 원칙) |
| `src/ipsm/backup.py` | 백업·복원 · 모든 쓰기가 여기를 거친다 |
| `src/ipsm/layout.py` | 편집 문서 — 이동·취소·변경 목록. 옮길 수 있는지는 여기서만 판단한다 |
| `src/ipsm/icons.py` | 아이콘 PNG 저장소 (임시 폴더 — 잃어도 되는 것) |
| `src/ipsm/apple_devices.py` | Windows 쪽 준비물 확인 — 27015 이 열려 있는가 |
| `src/ipsm/i18n.py` / `translations_en.py` | 말 — 한국어 원문이 열쇠, 로그는 옮기지 않는다 |
| `src/ipsm/ui/` | 화면 — Qt 를 아는 곳은 여기뿐이다 (`guide.py` 가 시작 안내판) |
| `src/ipsm/app.py` | 편집 창 진입점 |
| `src/ipsm/probe.py` | 실기기 진단 CLI |
| `tests/test_core.py` | 기기 없이 확인 가능한 것들 — `python tests/test_core.py` |
| `install.bat` / `install.ps1` | 의존성 설치 (`lzfse` 빌드 회피) |
| `run_app.bat` | 편집 창 실행 wrapper |
| `build_exe.bat` / `HomeSpread.spec` | 실행 폴더 만들기 |
| `src/ipsm/product.py` | 제품 이름·부제·후원 주소 — 선언 한 곳 |
| `src/ipsm/paths.py` | 자료 폴더 위치 — exe 로 묶였을 때는 exe 옆 |
| `src/ipsm/ui/about.py` | 정보 창 — 판·라이선스·원문 (창 안에서 읽는다) |
| `scripts/gen_notices.py` | 설치된 것을 읽어 라이선스 고지를 다시 쓴다 |
| `PRIVACY.md` | 개인정보 처리방침 (한국어·영어) — 스토어가 요구하고, 정보 창에서도 읽힌다 |
| `_workspace/05_store-submission-checklist.md` | 스토어 제출 점검표 — 무엇이 확인됐고 무엇이 남았는가 |
| `run_probe.bat` | 프로브 실행 wrapper |

## 후원

설정 창(도구모음의 **설정**) 아래에 PayPal 후원 단추가 있다. 눌러야만 기본 브라우저가
열리고, 창을 띄우는 것만으로는 아무 데도 연결하지 않는다. 받는 계정은
`src/ipsm/product.py` 한 곳에만 적혀 있다.

주소에 `no_recurring=1` 을 실어 정기 결제 칸을 접어 둔다 — 한 번 응원하려던 사람이
매달 빠져나가는 것을 뒤늦게 아는 일이 없어야 한다.

> **스토어에 올릴 때:** Microsoft Store 정책 10.8.2 는 *대가 없는* 자발적 후원에
> 한해 외부 결제(PayPal 같은 secure third-party purchase API)를 허용한다. 후원의
> 대가로 기능을 더 주거나 광고를 없애 주면 그 순간 Microsoft 인앱 결제 API 를 써야
> 한다. 그래서 이 단추는 **아무것도 주지 않는다.** 제출할 때 Partner Center 에
> third-party purchase API 사용을 신고해야 하고, 결제 직전에 결제 제공자가 누구인지
> 밝혀야 한다(단추에 PayPal 이라고 적혀 있는 이유).

## 라이선스

**HomeSpread 는 GPL-3.0-or-later 다.** 원문은 [`LICENSE`](LICENSE).

고른 것이 아니라 따라온 결과다. 기기와 말하는 일을 `pymobiledevice3` 가 하는데
그것이 GPL 이고, 함께 묶어 내보내는 순간 전체가 GPL 이 된다. 대안(`libimobiledevice`
계열)으로 갈아타 비공개 배포를 노릴 수도 있었지만, 이 앱은 남의 홈화면을 통째로
덮어쓰는 프로그램이다. **무엇을 쓰고 무엇을 쓰지 않는지 남이 읽어서 확인할 수 있는
편이** 그 일에 어울린다.

받는 사람이 갖는 것: 쓸 자유, 뜯어볼 자유, 고칠 자유, 고친 것을 다시 나눠 줄 자유.
대신 나눠 줄 때 같은 자유를 함께 넘겨야 하고, 보증은 없다.

### 함께 실려 오는 것들

함께 실려 오는 라이브러리의 이름·판·라이선스와 **원문**이
[`THIRD-PARTY-NOTICES.md`](THIRD-PARTY-NOTICES.md) 와 `third_party_licenses/` 에 있다.
손으로 적지 않는다 — 목록은 `pip install` 한 번에 낡고, 낡은 고지는 고지하지 않은
것과 같다. 다시 만들려면:

```powershell
.\.venv\Scripts\python.exe scripts\gen_notices.py
```

원문은 프로그램 안에도 함께 실린다. 실행 파일만 건네받은 사람도 **정보** 단추로 읽을
수 있어야 하기 때문이다.

소스는 <https://github.com/humanlyj/HomeSpread> 에 있다. GPL 은 실행 파일을 받은
사람에게 소스를 받을 길을 함께 주기를 요구하므로, 이 주소는 `product.SOURCE_URL` 에
적혀 있고 정보 창이 링크로 보여준다. 저장소를 옮기면 그 선언부터 고친다 — 닿지 않는
주소는 없는 주소와 같고, GPL 아래에서 그것은 의무 불이행이다.
